> 目标：为已生成的 25 个 `module.yaml` 补齐方法论内容。**不要改 `module.yaml`**，不要改其他模块，不要改内核代码。

   - `assets/modules/investment-map/SKILL.md`：九类投资出口、九类检索词、7+N 分表口径。
5. 本机已安装的 Anthropic Finance skills（只参考方法论与表格表达，不复制代码/模板）：
   - `~/.dsh/skills/datapack-builder/SKILL.md`
   - `~/.dsh/skills/comps-analysis/SKILL.md`
   - `~/.dsh/skills/3-statement-model/SKILL.md`

## 每个模块的交付物

```
assets/modules/<slug>/
├─ SKILL.md               # 120–260 行，方法论
├─ prompts/collect.md     # 40–80 行，任务模板
├─ rules/gates.json       # 声明式门；可为 {}
├─ rules/rubric.md        # 五维 1–5 分
└─ fallback.md            # 可选；未 stable 方向的最低调查清单
```

## 硬性要求

- **中文**；术语与旧 skill 一致；不写投资建议，只写调查方法与边界。
- 每条方法论都要可执行：查什么源、用什么词、怎么判 found/not_disclosed、哪些只能 pending_dd。
- 不编造具体 URL、公告编号、比例、金额；示例用占位符（A公司、平台P01、实体E01）。
- 六态必须出现在字段说明里；公司特定事实禁止用同行均值替代。
- 任务模板使用变量：`{{company.name}}`、`{{company.code}}`、`{{project.client}}`、`{{artifact:<type>}}`、`{{params.<key>}}`、`{{module.name}}`、`{{unit.partition}}`。
- `rules/gates.json` 只允许这些键：`minEvidence`、`minCoverage`、`requiredFields`、`minItems`、`sixStateFields`、`maxEstimatedRatio`、`consistency`。
- `rules/rubric.md` 五维：事实准确性 / 引用准确性 / 完整性 / 来源质量 / 对账；写清 3 分与 5 分判据。
- 模块状态一律 `draft`；不得声称 `stable` 或“专家已审”。
- 只写自己负责的模块目录；目录不存在时创建。
- 完成后报告：写了哪些文件、每个模块的核心检索路径、已知缺口。

## 模块分组

**M1 核心闭环（6）**：entity-resolution、ownership-chain、investment-map、red-flags、deliverable、generic-investigation。

**M2 业务/技术/市场（8）**：related-parties、business-segment、customers-orders、supply-capacity、market-landscape、ip-portfolio、tech-origin、qualifications。

**M3 人/财务/风险/评估（11）**：org-people、workforce、financials-public、financing-history、debt-guarantee、legal-risk、regulatory-compliance、policy-exposure、esg-ehs、public-sentiment、assessment-fit。

## 特别说明

- `entity-resolution`：输入是项目目标清单（company.roster），输出 company.identity；重点是全称/简称/曾用名/代码/注册地/成立日/状态/实控人线索；名称唯一、代码校验、≥2 源。
- `ownership-chain`：逐层穿透、直接+间接、一致行动、特殊权利、历次变更；合计≈100%、口径标注；控制结论放这里，不在 identity 重复。
- `investment-map`：九类出口；平台编号 P01 稳定；平台级明细分区；每平台≥3 证据；方向口径只查“A公司系投出去”，不查“谁投了 A公司”。
- `red-flags`：12 条触发器只生成核查项；重大风险进摘要首页，不阻断交付；一致性失败才阻断。
- `deliverable`：这是构建器，不是检索模块；写清摘要 5–10 条、综合工作簿、7+N、底稿包、QA、签发；报告不得创造底稿之外的新事实。
- `generic-investigation`：没有专用模块时的兜底；material claim 证据覆盖 100%；`not_found` 必须附 search.ledger；报告只从 claims 生成；不得要求脚本/子代理才能跑。
- `policy-exposure`：类型是 draft；清单版本、实体匹配、适用范围、替代方案；不自动否决。
- `financials-public`：会计口径、审计意见、期间、币种、合并范围、原始/重述；三表勾稽；不要只写文本结论。
- `assessment-fit`：拆成技术/商业合作适配与股权投资判断；后者只作 IC 输入。
