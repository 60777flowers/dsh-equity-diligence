# 《实现审核报告》整改诊断与施工计划

> 审核对象：`docs/实现审核报告.md`（2026-11-07）
> 结论：报告 P0 大部分成立，且多数是“交付可信度”问题，不是重构洁癖。按 **先堵数据失真、再补主体泛化、最后做体验** 的顺序整改。
> 原则：**不为了让演示通过而放宽门**；修不了的结构性问题明确降级/标注，不伪装成已解决。

## 1. 逐项诊断

| 编号 | 报告问题 | 复核结论 | 是否本轮修改 | 处理口径 |
|---|---|---|---|---|
| A1 | 交付读 `current`，draft 可交付，`verified` 指针不失效 | **成立**：`package.js` 用 `listArtifacts`，`check.js` 只拦 stale/rejected | **是（P0）** | 三指针生命周期；交付只消费 currentVerified；draft/stale/rejected 不进交付；QA 阻断 |
| A2 | Agent 可自报 verified/human；signoff 无 QA 门禁 | **成立**：工具暴露 status/actor；`service.signoff` 不校验 QA、signedAt 可传 | **是（P0）** | 工具只写 draft/agent；signoff 用户专属、重读交付物、校验 QA + hash、服务端时间 |
| A3 | 无锁、无 CAS、幂等缺失 | **成立**：`recordArtifact` 读 current 再 +1；runner 不传 expectedRev；concurrency 未使用 | **是（P0）** | 进程内/文件锁 + CAS；requestId 去重；UnitKey 加 inputPins；concurrency>1 明确报错或真正串行 |
| A4 | stale 哈希不同源；`investigationComplete` 不可达 | **成立**：runner 写 rendered prompt hash，计划存 module hash；`stepForRecord` 用 unitId 比 instanceId；producedBy 还丢掉 templateSha | **是（P0）** | 统一 codeVersion；producedBy 写 instanceId/templateSha；单测同版本不 stale、换模板 stale |
| B1 | 混合 code 与 `code→listed` | **成立**：`project.js` 有 code 即 listed；listingStatus 不读 | **是（P0）** | 删除推断；新增 `identifiers[]`（scheme/value/issuer/jurisdiction/status）；listingStatus 独立、默认 unknown |
| B2 | 名称 slug 主键；解析不回写；多目标只查第一个 | **成立**：`subjectIdFor` slug；`buildVars` targets[0]；identity 不回写 roster | **是（P0，最小闭环）** | 新增稳定 `entityId`（USCC 优先，否则名称 hash）；unit 用 own target 渲染；identity 结果回写 roster；旧项目保留 legacy subjectId 兼容 |
| B3 | 未上市被门结构性判死 | **成立**：financials-public 必填 revenue/netProfit/recon≥3，SKILL 说非公众走 not_disclosed | **是（P0）** | 门按 listingStatus 分支；非公众走 fallback；`not_disclosed_after_search` 不被必填/证据门误杀 |
| C1 | 体检单硬编码通过 | **成立**：`package.js` 写死 qa passed，真 QA 在构建后 | **是（P0）** | 先构建→真 QA→回写 QA 后重建 10_体检单；空项目/无证据阻断 |
| C2 | 7+N 核心 14 列为空，实控人被默认“否” | **成立**：investment.map entities 无 entityId，builder 联接失败；`founderControl ? 是 : 否` | **是（P0）** | entities 增 entityId；联接统一；无数据 `not_reviewed`，不得写“否” |
| C3 | 13 份业务底稿只落 7 份 workpaper | **成立**：按 module slug + 固定文件名互相覆盖 | **是（P0）** | 路径含 artifactId（或 subject/partition 安全段）；底稿与 workpaper 一一对应 |
| C4 | 02–05 默认 found、证据列为空 | **成立**：row 默认 found；多数调用不传 status/evidence | **是（P0）** | 状态由值推导；空值不得 found；证据列填 claim/evidence；Python 增加空值+found 阻断 |
| D1 | 任意目录建项目；preset 路径穿越 | **成立**：`web-api` 展开 body；`createProject` 只 resolve；`loadPreset` join 无校验 | **是（P0）** | root 限工作区/已登记项目；preset 固定白名单；HTTP body 白名单；拒绝 `..` |
| D2 | signoff/record 权限与审计可伪造 | **成立**（同 A2） | **是（P0）** | 与 A2 合并；工具层移除 decide；用户动作只走用户通道 |
| D3 | 全局索引无租户，绝对路径回浏览器 | **成立，但单机产品可接受** | **是（文档级）** | README 明确“单用户/单机”；远程/多客户前必须加租户，列为后续门 |
| D4 | 交付页 `qa.blocking` 数字/数组不一致必崩 | **成立**：service 存 `.length`，client `.map` | **是（P0）** | 统一数组；client 兼容旧形状；ErrorBoundary |
| E1 | quote 伪快照，可被改写 | **成立**：enrich 只算 verificationStatus，门不要求 verified | **是（P0）** | material claim 的 supports 必须 verified；quote 不命中→partial 并阻断 material |
| E2 | 空 claim 也能 verified | **成立**：无 claim 的底稿可 verified | **是（P0）** | 业务底稿最少 claim/evidence（模块声明优先）；空 claim 不得 verified |
| E3 | 跨币种/股债混加 | **成立，但属数据建模** | **否（P1）** | 7+N 融资总额按币种分组/标注；需 schema 变更，排 P1 |
| E4 | VIE/境外断链未结构化 | **成立，但属产品能力** | **否（P1）** | 境外/VIE 显式 chainBreak；需关系模型，排 P1 |
| E5 | 空数组写成“无诉讼/无失信” | **成立**：valueText 空数组/空值处理弱 | **是（P0）** | 空数组 → `not_reviewed`；不得写“无”；法律/监管行无证据不得 found |
| E6 | 缺交易层/IC 问题层 | **成立，属产品范围** | **否（P2）** | 列为后续产品包；不在本轮伪造 |
| UI P1 | verify 实际 build、issues 死链、busy 死锁、i18n/XSS | 部分成立 | **部分（P0 相关）** | 只修交付页崩溃/错误边界/verify 真校验；其余排 P1 |

## 2. 本轮施工分组

### Wave 1（并行，文件不重叠）

| 组 | 负责 | 文件 | 验收 |
|---|---|---|---|
| K 内核真实性 | A1/A2/A3/A4/D2 | `src/kernel/artifacts.js`、`stale.js`、`runner.js`、`state.js`、`src/service.js`（record/signoff/readiness）、`src/tools.js`、`tests/artifacts.test.js`、`tests/state.test.js`、`tests/pipeline.test.js` | 三指针/签名/锁/CAS/stale 单测；golden 仍过 |
| D 交付真实性 | C1/C2/C3/C4/E5 | `src/builders/package.js`、`check.js`、`python/build_workbooks.py`、`python/check_deliverable.py`、`tests/delivery-review.test.js` | 13 底稿→13 workpaper；10_体检单与 QA 一致；7+N 空值 not_reviewed；空项目阻断 |
| S 权限/UI 阻断 | D1/D4/D3(文档待办) | `src/web-api.js`、`src/kernel/registry.js`、`client.js`、`tests/api.test.js`、`tests/ui-contract.test.js` | 路径穿越 400；preset 白名单；交付页数字/数组都不崩 |
| I 主体泛化 | B1/B2/B3 | `src/kernel/project.js`、`render.js`、`ids.js`、`migrate.js`、`assets/artifact-types/{company.roster,company.identity,investment.map}.json`、`assets/modules/financials-public/rules/gates.json`、`client.js`（仅新建表单） | code 不再推 listed；多目标各查各；只填公司名能开工；非公众不被门判死 |

> K/D/S 先并行；I 在 K 完成后接手 `render/runner` 的 target 透传，避免同文件冲突。D 的 `investment.map` schema 变更需与 I 错开：若 D 先改 entityId，I 后补 identifiers。

### Wave 2（验收）

| 验收组 | 验收内容 |
|---|---|
| VK | 构造 draft/stale/rejected 底稿，确认不进交付；并发 recordArtifact 只有一个成功；同版本不 stale、换模板 stale |
| VD | golden 构建 14 份底稿（含 roster resolution）/14 workpaper；10_体检单=真 QA；空项目/空 claims 阻断；7+N 无数据不写否 |

## 3. 明确不在本轮做

- E3 跨币种融资汇总（需 schema/口径设计，P1）
- E4 VIE/境外断链结构化（需关系模型，P1）
- E6 交易层/IC 问题层（P2）
- 多租户/远程权限（P2；README 明确单用户）
- 25 模块专家评审（后续门）
- UI P1 的 i18n、深色模式、完整可访问性（P1）
