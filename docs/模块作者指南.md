# 模块作者指南

> 目标：让一个分析师/工程师在**不写运行时代码**的前提下，新增一个可编译、可运行、可交付、可体检的调查模块。

## 1. 目录

```
assets/modules/<module-id>/
├─ module.yaml          # 身份、版本、输入/输出、门、预算、参数
├─ SKILL.md             # 方法论（给模型看，必须具体）
├─ prompts/collect.md   # 任务模板（stub 变量）
├─ rules/gates.json     # 机器可判定规则
├─ rules/rubric.md      # 5 维质量 rubric（人工/模型评审）
└─ fallback.md          # 工具不可用时的降级说明
```

模板与公共片段：`assets/modules/_shared/`（`MODULE_TEMPLATE.md`、`_system.md`、`_tail.md`）。

## 2. module.yaml 最小示例

```yaml
apiVersion: equity.module/v1
id: builtin/example-check
name: 示例核查
version: 0.1.0
status: draft
provenance:
  author: <你的标识>          # 必填：谁写的。子代理写就填子代理标识
  origin: human               # 必填：human（人工编写并负责）| agent（子代理初稿，待接管）
stage: risk
compat:
  kernel: ">=1.0.0 <2.0.0"
inputs:
  - type: company.identity
    onMissing: block
  - type: legal.risk
    onMissing: degrade
outputs:
  - type: document.markdown
    scope: company
    cardinality: one
gates:
  - id: schema
    type: schema
  - id: coverage
    type: coverage
    config: { min: 0.7 }
  - id: rules
    type: rule
    config: { minEvidence: 2 }
budget:
  maxWallClockMin: 20
  maxTokensPerUnit: 120000
  toolCallsPerUnit: 12
```

规则：
- `id` 必须全局唯一，建议 `builtin/<kebab>`。
- `version` 用 semver；`status` 只能是 `draft/stable/deprecated`。
- **`provenance.author` / `provenance.origin` 必填**，用于区分作者与来源：`origin: human` 表示人工编写、作者对该方法论负责；`origin: agent` 表示子代理初稿。**人工接管子代理初稿时，把 `author` 改成接手人、`origin` 改成 `human`**——这是显式的责任转移，不要悄悄改。缺字段记 `missing_provenance` warning，`origin` 非法直接报错。可选 `derivedFrom` 写明方法论来源（如某个旧 skill 的版本）。
- 输出类型必须在 `assets/registry/types.json` 注册；新增类型先提 schema 变更。
- `onMissing: block` 是硬依赖；`degrade` 是软引用，不参与环检测。
- `scope: company/project`；`cardinality: one/many` 由**类型 schema** 声明；`many` 时执行器按 `partitionKey` 产出多份（如 `investment.map` 的 `_summary` + `P01…`），模块 manifest 不单独声明。
- 不要输出其他模块的“结论型”字段；控制权归 ownership，估值归 valuation。

## 3. SKILL.md 写法

至少包含：

1. **回答什么问题**、不回答什么；
2. **数据源优先级**（公告/招股书/工商/官网/媒体）与最低证据数；
3. **6–10 步调查步骤**，每步写清“查什么、去哪查、怎么记”；
4. **字段口径**（时点/期间、合并口径、比例分母、金额单位）；
5. **六态写法**：查不到写 `not_disclosed_after_search` + 检索路径；未核写 `pending_dd`；下限写 `lower_bound`；冲突写 `conflict`；
6. **红旗/核查触发器**：只写“需核什么”，不定性；
7. **输出 JSON 的硬约束**：schema、必填、claimId/evidenceId 格式；
8. **降级**：工具不可用时怎么用用户材料/公开文件完成最小可用版本。

禁止：把“未查到”写成“无”；把估算写成 found；把媒体传闻写成事实；把风险写成否决结论。

## 4. prompts/collect.md

可用变量：

```
{{project.name}} {{project.asOf}} {{project.engagement.clientName}}
{{target.name}} {{target.code}} {{target.jurisdiction}}
{{module.id}} {{module.version}}
{{inputs}}            # 已 pin 的上游底稿 JSON
{{fallbackCards}}     # 可用降级卡
{{outputSchema}}      # 目标类型 JSON Schema
{{budget}}            # 剩余预算
```

要求：
- 明确“只输出一个 JSON 对象”，不要 Markdown 包裹；
- 明确 claim 的 `subjectId`、`asOf`、`confidence`；
- 明确 evidence 的 `quote` 必须是原文**逐字**片段，否则验证会失败；
- 明确 material claim 至少一条 `supports`。

## 5. rules/gates.json

支持字段：

```json
{
  "minEvidence": 2,
  "minCoverage": 0.7,
  "requiredFields": ["data.legalName"],
  "minItems": { "data.identifiers": 1 },
  "sixStateFields": ["data.controllingPerson"],
  "maxEstimatedRatio": 0.3,
  "consistency": [
    { "id": "sum100", "kind": "sumTo100", "field": "data.capTable[].totalPct", "tolerance": 1, "onFail": "block" }
  ]
}
```

`consistency.kind` 常用：`range`、`enumMember`、`uniquePair`、`sum`、`sumTo100`、`crossFieldEqual`、`requiredWhen`、`requiredFieldsWhen`、`setEquals`、`setCovers`、`subset_of`、`refExists`、`forbiddenText`、`coverage`、`requiresLedger`、`countMatches`、`crossRef`、`contains`、`regex`、`mustBeEmpty`、`order`。

`onFail`：
- `block` / `issue`：阻断该底稿验收，进 `needs_human`；
- `warn` / `attention`：只记 warning/issue，不阻断；
- 省略：默认阻断（结构性规则）。

## 6. 测试模块

1. 在 `tests/fixtures/<project>/module-outputs/<instance>.json` 放一个**通过门**的输出；
2. 用 `equity_record` 或 `recordArtifact` 写入，确认 schema/gates 通过；
3. 至少构造一个反例（缺必填/比例超 100/证据不足），确认门会拦；
4. 运行 `node tools/validate-assets.mjs`，确认模块被加载且预设可编译；
5. 若新增输出类型，先更新 `assets/registry/types.json` 与 `assets/artifact-types/*.json`，再跑 `tools/gen-modules.mjs`。

## 7. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `missing_producer` | 输入类型没有模块产出 | 加 producer 或改 `degrade` |
| `cycle_detected` | 硬依赖成环 | 改软引用/拆模块 |
| `order_violation` | 消费者排在生产者之前 | 调整 `stage` 或顺序 |
| `duplicate_producer` | 两个模块声明同一输出类型 | 合并或拆 merge 模块 |
| `schema` 门失败 | 输出缺字段/类型错 | 对照 `outputSchema` 修正 |
| `coverage` 门失败 | 检索尝试/维度不足 | 补来源或降低阈值（需说明） |
| `evidence` 门失败 | material claim 无 supports | 补原文证据 |
| `stale` | 上游 revision/hash 变化 | 重跑本模块或确认口径 |

## 8. 何时可标 stable

必须同时满足：
- **已由人工接管**（`provenance.origin = human`，作者是可指名的人）：子代理初稿不得直接标 stable；
- 金融专家评审通过（方法论、口径、阈值、触发器）；
- 至少 2 个真实项目/2 个行业样本验证；
- 反例/边界用例通过；
- gates 无误报/漏报记录；
- 版本升级有兼容说明与迁移路径。

在此之前保持 `draft`，UI 会显示 `DRAFT` 徽标，交付 QA 会提示“模块未 stable”。
