## 1. 包与安装

- 包名：`dsh-equity-diligence`；插件行 id：`equity-diligence`；命令：`/equity`；技能：`equity-diligence`。
- 纯 ESM、零运行时 npm 依赖；只用 Node 内置模块与 `ctx` 服务。
- `package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`；`dsh.client.platform = web`，`exports["./client"] = ./client.js`。
- 安装：`dsh plugin --profile web add "link:<abs path>"`，再在 profile `cordis.patch.yml` 插入本包行；热加载由 profile 的 `patchReload: live` 负责。
- 回滚：删除 patch 行，`dsh plugin --profile web remove dsh-equity-diligence`；脚本见 `tools/install-local.ps1` / `tools/rollback-local.ps1`。

## 3. 底稿（Artifact）

### 3.1 记录信封

```jsonc
{
  "schemaVersion": 1,
  "id": "art_01J...",
  "type": "company.identity",
  "typeVersion": 1,
  "scope": "company",                    // company | project
  "subjectId": "co_example",
  "partitionKey": "_default",
  "period": { "asOf": "2026-09-30", "start": null, "end": null },
  "status": "draft",                     // draft | verified | stale | rejected
  "revision": 1,
  "contentHash": "sha256:...",           // semanticDataHash
  "presentationHash": "sha256:...",
  "codeVersion": "entity-resolution@0.1.0+tmpl:...",
  "data": { /* 类型 schema */ },
  "claimIds": [],
  "evidenceIds": [],
  "derivedFrom": [
    { "artifactId": "art_...", "type": "company.identity", "kind": "input",
      "revision": 1, "contentHash": "sha256:...", "fieldPaths": [] }
  ],
  "checks": [ { "id": "schema", "status": "pass", "detail": "" } ],
  "producedBy": { "moduleId": "builtin/entity-resolution", "moduleVersion": "0.1.0",
                  "runId": "run_...", "unitId": "unit_...", "actor": "agent" },
  "asOf": "2026-09-30",
  "openQuestions": [],
  "flags": [],
  "sourceCoverage": { "queries": [], "databases": [], "retrievedAt": "..." },
  "createdAt": "2026-11-07T00:00:00+08:00",
  "updatedAt": "2026-11-07T00:00:00+08:00"
}
```

- 逻辑主键：`type + scope + subjectId + partitionKey + period/asOf`。
- `cardinality=many` 必须给稳定 `partitionKey`（平台号 `P01`、实体 ID、财年 `FY2025`、案件号、模块实例）。
- 三指针：`current.json`（latest）、`verified.json`（currentVerified）、`running.json`（runningRevision）；失败 Attempt 不覆盖 `verified.json`。
- `contentHash` 只对 `data` 做规范化哈希；`presentationHash` 对渲染文本做哈希；LLM 换措辞不触发下游 stale。

### 3.2 状态机

```
draft --checks pass--> verified --stale--> stale --rerun+pass--> verified
  ^                                  |
  +-- checks fail（留 draft + issue） +-- human reject --> rejected
```

- `checks fail` 不直接 `rejected`；`rejected` 只能人工。
- `stale` 由内核按规则计算，不向下游传递；`affected` 只做 UI 提示。
- `blocked` 是 Unit 状态，不是 Artifact 状态。

### 3.4 六态字段

所有业务字段必须是以下之一，且带 `note`；不得为空：

`found / not_disclosed_after_search / lower_bound / pending_dd / conflict / not_applicable / not_reviewed / estimated`

- `not_disclosed_after_search` 必须关联 `search.ledger` 的尝试记录。
- `estimated` 只允许分析型字段，必须带 `derivation {method, inputs[], comparables[], assumptions[]}`。
- 公司特定事实（第一大股东、前五大合计、股东数、累计融资）不得用同行均值替代。

## 4. Claim 与 Evidence

### 4.1 Claim

```jsonc
{
  "claimId": "cl_...",
  "subjectId": "co_example",
  "predicate": "largest_shareholder_pct",
  "value": 42.5,
  "unit": "percent",
  "period": { "asOf": "2026-09-30" },
  "status": "found",
  "materiality": "material",             // material | attention | context
  "evidenceLinks": [
    { "evidenceId": "ev_...", "role": "supports", "locator": "p.4 ¶2", "rawHash": "sha256:..." },
    { "evidenceId": "ev_...", "role": "contradicts", "locator": "p.8 table 1" }
  ],
  "derivation": null,
  "note": ""
}
```

- `material` claim 的 `evidenceLinks` 必须至少一条 `supports`；否则只能进 `openQuestions`。
- 冲突保留全部候选、期间口径、`chosenClaimId`、`resolutionRationale`、`decidedBy`（放 `conflictGroup`）。
- `originGroupId` 去重同源转载；两个转载同一新闻稿不算独立双源。
- 四维评分：`sourceAuthority / sourceIndependence / verificationStatus / claimConfidence`，不合并。

### 4.2 Evidence

```jsonc
{
  "evidenceId": "ev_...",
  "url": "https://...",
  "finalUrl": "https://...",
  "title": "...",
  "quote": "原文片段",
  "locator": "p.4 ¶2",
  "sourceTier": "announcement|registry|regulator|court|exchange|company|media|database|import|sample",
  "sourceAuthority": "A|B|C|D",
  "sourceIndependence": "independent|same_origin|self_reported|unknown",
  "verificationStatus": "verified|partial|unreachable|unverified",
  "claimConfidence": "high|medium|low",
  "asOf": "2026-09-30",
  "publishedAt": "2026-08-01",
  "retrievedAt": "2026-11-07T00:00:00+08:00",
  "rawHash": "sha256:...",
  "originGroupId": "og_...",
  "verification": { "method": "quote-exact|manual|import", "checkedAt": "...", "matches": true },
  "snapshotPath": ".equity/evidence/blobs/<sha256>.txt"
}
```

- 证据原文不可变；`rawHash` 指向 blobs，不指向可删缓存。
- 非 2xx、`truncated`、`finalUrl` 变化、引文未命中都要显式记录；引文未命中不能直接证伪结论。
- 证据写入唯一入口：`equity_record(kind=evidence)`；模块白名单只写 `equity_record`，不存在 `equity_evidence`。

## 6. 方案编译

1. 解析 `playbook.yaml`，校验 `apiVersion/id/name/version/modules`。
2. 解析每个 `use: builtin/<id>@<range>`；范围不满足 → `version_unsatisfied`。
3. 建“类型 → 生产者实例”索引；同一类型两个启用实例 → `duplicate_producer`（R1 唯一生产者）。
4. 每个 `inputs[].onMissing=block` 找生产者；找不到 → `missing_producer`；`degrade` 不建硬边。
5. `references` 找不到 → `dangling_reference`（warn），不参与环检测。
6. `all` 在编译期展开为 registry 中 `status != legacy` 的显式类型列表，排除自身输出、`report.deliverable` 与系统类型；展开结果进入快照。
7. 只用 `block` 硬边建图，拓扑排序；环 → `cycle_detected`。
8. 方案列表顺序与拓扑序冲突 → `order_violation`（error，附 `suggestedOrder`）。
9. 未知类型/工具/阶段 → `unknown_artifact_type` / `unknown_tool` / `unknown_stage`（后两者按 error/warn 表）。
10. 产出 plan：`steps[]`、`edges[]`、`gates[]`、`budget`、`snapshotHash`。

编译错误行内定位（`moduleIndex`、`field`、`path`），并给一键重排。

## 7. Runner

- `UnitKey = moduleInstance + subject + partition + resolvedParams + inputPins` 的规范化哈希。
- 先物化系统单元 `system/source-acquisition`（生成 `search.ledger`、`source.coverage`），再按拓扑跑业务单元。
- 每个单元：解析输入 revision/hash → 检查上游 verified → 渲染 prompt → 执行器 → schema 校验 → gates → 写 artifact → 核查触发器 → 事件。
- 幂等键命中且 `verified` 存在、产物文件存在、contentHash 一致 → 跳过。
- 失败分类：`rate_limit / timeout / schema_invalid / blocked / unparsed / gate_failed / budget_exhausted / provider_error / needs_human`。
- `paused / budget_exhausted` 不是 failed；`needs_human` 不自动重跑。
- 并发：collect 默认 2（上限 6）；synthesize/deliver 串行。
- 检查点：每个单元结束写 `units.json` + `events.jsonl`；重启按 `units.json` 对账，已 accepted 不重复。
- 预算：单元级 + 方案级取小；触顶保存现场并标 `budget_exhausted`。

## 8. 核查触发器

12 条触发器 T1–T12 的输出：

```json
{ "triggerId": "T2", "subjectId": "co_example", "period": {"asOf": "..."},
  "status": "hit|miss|insufficient", "action": "核对是否已披露、交易方向/金额/期间/定价/审批",
  "level": "attention|material", "evidenceLinks": [], "inputs": [] }
```

- 触发器只产生 `review_trigger`，不阻断交付；重大风险进摘要首页。
- 一致性检查（报告数字 ≠ 底稿、同口径矛盾、未处理 stale/rejected）才阻断交付。


- 摘要 5–10 条，每条“事实 → 影响 → 证据强度 → materiality → 下一步”，挂 `claimId`。
- 综合工作簿：目录、摘要、主体股权、业务技术、财务、风险、待核、资料请求、来源索引、底稿索引、体检。
- 7+N：7 张固定 + 至多 3 张家族 + 说明；24 列 → 清理版 20 列；行 = 平台路径 × 实体；多路径各表各一行；标绿由确定性规则完成。
- `cellMap` 每条 pin `artifactId + revision + contentHash + runId + claimId`。
- 体检：结构、列语义、六态、血缘、stale、公式、摘要与底稿一致性；阻断项与非阻断项分开。
- 复核：`preparedBy / reviewedBy / approvedBy`；Agent 只能 `proposeReview`。

## 12. UI 数据契约

- 首屏三问：查了没有（覆盖/进度）、查得对不对（证据/冲突/审核）、能不能交（QA/签发）。
- 五个页签：总览、方案、底稿、运行、交付。
- 证据抽屉：URL、引文、抓取时间、rawHash、四维评分、原文快照。
- 状态色只使用语义色：verified 绿、attention 琥珀、material/error 红、stale 灰黄、running 蓝、draft 灰。
- 设计语言参考 Anthropic Finance skills：海军蓝/浅蓝/灰、白底、细边框、数字等宽、表格密集、无装饰性图表、无渐变；深色模式用 DSH token。

## 13. 验收

1. `node --test tests/*.test.js` 全绿。
2. skill-only / quick / standard / deep / generic 全部静态编译通过；缺生产者、环、顺序、重复生产者、未知类型有负例。
3. golden 项目：1 公司 / 1 平台 / 2 实体 / 双路径；fixture 执行器跑通；产出 MD + xlsx + manifest + QA；三跳追溯可达。
4. 断点恢复：kill 后重启不重复提交已 accepted 单元。
5. stale：上游内容变、代码变、依赖集合变、过期、rejected 五类有测试；代码变不自动波及下游。
6. 迁移：旧目录副本导入为 draft，原文件不破坏。
7. 安装：web profile 工具可用、面板可见、API 200；回滚脚本可恢复。
8. 联网 smoke：可用时 1 公司/1 平台跑一次；不可用时明确报告 `provider_unavailable`，不产生低质量结论。
