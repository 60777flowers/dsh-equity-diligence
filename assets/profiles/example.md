# 委托方背景（内置模板 · 请改写后使用）

> 用途：本文件是 `assessment-fit` 等模块评估"技术关联 / 合作潜力"的**内置对照基准**。项目创建时会被复制为该项目 `00_基准/委托方背景.md`，供各模块渲染时注入。
>
> 读取优先级：项目内 `00_基准/委托方背景.md`（非空，可人工改写，**优先**）> 本内置模板。
>
> 使用方式（三选一）：
> 1. 立项后直接改写项目里的 `00_基准/委托方背景.md`（推荐，只影响本项目）；
> 2. 复制本文件为 `assets/profiles/<你的id>.md`，并在方案里把 `assessment-fit` 的 `params.clientProfile` 指向该 id（影响所有引用它的项目）；
> 3. 保持本模板不动，此时评估模块只能得到通用的"环节匹配"判断，**结论强度应相应下调**。
>
> 纪律：**禁止联网搜索、禁止编造委托方背景**。委托方的技术边界、采购口径、禁区只以本文件或项目内背景文件为准。

## 1. 委托方是谁

- 名称：待填写
- 性质：待填写（产业方 / 财务投资人 / 平台公司 / 政府基金 …）
- 主营与所处环节：待填写（例如"上游材料—电子特气"）
- 规模与阶段：待填写

## 2. 技术与产品边界

- 核心产品线：待填写
- 关键技术节点 / 工艺路线：待填写
- 明确**不做**的方向（用于排除伪协同）：待填写

## 4. 采购与导入门槛

- 供应商认证流程：待填写（送样 → 单项验证 → 小批量 → 量产导入 …）
- 认证周期：待填写（如 12–24 个月）
- 导入的关键门槛：待填写（良率、产能、交期、合规、认证资质 …）

## 5. 合作评估对照要点（a / b / c / d）

评估模块默认按以下四条对照，可按委托方实际情况改写：

- **a) 环节匹配**：目标公司产品/技术是否落在上表列出的委托方所需环节？
- **b) 验证记录**：是否已有进入委托方或主流厂商供应链的验证 / 量产记录？（有记录 = 合作潜力高）
- **c) 替代逻辑**：是否属于委托方亟需的国产替代 / 本地化 / 二供三供标的？
- **d) 技术路线**：技术路线是否与委托方现有工艺 / 平台兼容，切换成本多大？

## 6. 禁区与合规

- 不接触、不采集的信息：待填写（个人隐私、非公开数据、受限清单主体 …）
- 明确不做的判断：投资建议、估值结论、法律/审计/税务意见
- 涉外/出口管制敏感项：待填写
