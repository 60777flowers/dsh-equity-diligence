# 兜底清单 · 红旗核查（未 stable 方向的最低调查）

> 适用：上游底稿不齐、财务数据缺失、只跑 quick 预设、预算只够跑核心触发器。
> 兜底不改变“只生成核查项、不定性”的定位。模块状态 `draft`。

## 1. 最低必做（五项）

1. **12 条全部出现**：哪怕只是 `insufficient`，也必须写结果，不能缺项。
2. **每条命中挂证据**：至少一条 `supports`；无证据降级为 `insufficient`。
3. **每条 `insufficient` 有动作**：进 `ddRequests`，写缺什么、向谁要、为什么重要。
4. **口径留痕**：同主体/同期间/同币种/同口径，容差与调整理由写进 `inputs`。
5. **无定性用语**：不写违规、造假、利益输送、否决投资。

## 2. 分场景下限

| 场景 | 最低动作 | 允许的六态 |
|---|---|---|
| 只有工商与公告 | 跑 T10 诉讼、T11 处罚、T12 清单；其余标 `insufficient` | `hit/miss/insufficient` |
| 有年报但无明细 | 跑 T1 客户集中度、T7 境外收入、T8 人均成本、T9 估值 | 同上 |
| 无客户/供应商底稿 | T1/T3/T12 一律 `insufficient`，不得猜名单 | `insufficient` |
| 无专利/人员底稿 | T4/T5 `insufficient`，写“缺专利或人员数据” | `insufficient` |
| 无财务底稿 | T7/T8/T9/T10 `insufficient`，不估算财务数字 | `insufficient` |
| 只跑 quick 预设 | 至少 T1、T7、T9、T11、T12，其余 `insufficient` | `insufficient` |
| 舆情缺失 | T10/T11 备注“未做舆情维度”，不写 `miss` | `insufficient` |

## 3. 必须写进底稿的三句话

- 哪几条触发器因缺什么底稿只能 `insufficient`，补齐后能判什么。
- 哪些红旗是“需核查”，哪些是“已排除误报”，分别列。
- 重大红旗进摘要首页时，必须挂 `claimId` 与 `evidenceId`，不得只写结论。

## 4. 明确不做

- 不用同行均值判本公司异常。
- 不把媒体爆料、转载、自媒体解读当命中依据。
- 不把超过阈值直接写成“有问题”，只写“需核查”。
- 不因红旗命中阻断交付；阻断只来自一致性失败。
- 不在兜底模式下声称“已完成全部风险核查”。
