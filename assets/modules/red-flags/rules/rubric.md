# 审核 rubric · 证据矩阵与红旗清单

> 五维各 1–5 分；**任一维 ≤2 分即不通过**。评分看 `triggerResults`、`flags`、`ddRequests` 与证据原文。
> 模块状态 `draft`：本 rubric 尚未经金融专家评审。

## 1. 事实准确性（红旗与数值）

| 分 | 判据 |
|---|---|
| 5 | 红旗引用的金额、比例、日期与上游 claim 完全一致；同主体/同期间/同币种/同口径四项全对齐；无一处把 `insufficient` 写成命中 |
| 4 | 基本一致，个别数值只有单一来源但已标注 |
| 3 | 有 1–2 处口径未标（投前/投后、单体/合并），不影响结论 |
| 2 | 出现期间或币种混比、用同行均值判本公司异常 |
| 1 | 红旗与底稿数值矛盾，或凭空生成事实 |

## 2. 引用准确性（证据）

| 分 | 判据 |
|---|---|
| 5 | 每条 `hit` 与 `material` 红旗都有 `supports` 证据，`locator` 可回查；`claimMatrix` 的 `claimId` 全部可追溯 |
| 4 | 主要红旗有证据，个别为 `attention` 级且只到页面级 locator |
| 3 | 有 1–2 条 `hit` 仅凭媒体线索，已降级处理 |
| 2 | 多条红旗无证据，或引文无法命中 |
| 1 | 编造案号/处罚/金额，或无任何证据 |

## 3. 完整性（12 条与动作）

| 分 | 判据 |
|---|---|
| 5 | T1–T12 全部运行，含 `miss`；每条 `insufficient` 都有可执行的 `ddRequests`；误报排除逐条留痕 |
| 4 | 12 条齐全，个别 `miss` 缺 `inputs` 说明 |
| 3 | 12 条齐全，但 1–2 条 `insufficient` 未生成 `ddRequests` |
| 2 | 只跑了部分触发器，或 `insufficient` 与 `miss` 混用 |
| 1 | 只有红旗清单，没有触发器结果 |

## 4. 来源质量（source quality）

| 分 | 判据 |
|---|---|
| 5 | 以裁判文书/执行信息/处罚决定/公告为主，工商与权威媒体交叉；无 D 级来源进入命中 |
| 4 | A+B 为主，个别线索来自媒体并已回核 |
| 3 | 多数命中依赖工商快照与媒体 |
| 2 | 命中主要来自自媒体或转载 |
| 1 | 依赖传闻，未回原始文书 |

## 5. 对账（consistency）

| 分 | 判据 |
|---|---|
| 5 | 触发器集合完整且唯一；`flags` 与 `triggerResults` 一一对应不重复；红旗引用无悬空；无定性用语 |
| 4 | 对账通过，个别 `flags` 描述与 `action` 重复 |
| 3 | 有一条红旗未回链到触发器等小问题 |
| 2 | 同一事实拆成多条红旗，或引用不存在的 claimId |
| 1 | 红旗与触发器结果矛盾，或出现“违规/造假”等定性结论 |

## 判定与记录

- 五维分数与扣分点写入底稿 `checks[]`，扣分点挂 `triggerId`/`claimId`/`evidenceId`。
- 任一维 ≤2：退回补跑或补证，不得进入交付汇总。
- 3 分：可交付；`material` 红旗按规则进摘要首页，并在摘要标注“核查项，未定性”。
- 5 分：可直接作为 IC 风险输入，无需二次核对。
- 任何情况下，触发器命中都不阻断交付；只有一致性失败才阻断。
