# public-sentiment · 审核 rubric（五维 1–5 分）

> 适用：`public.sentiment` 底稿复核。任一维 ≤2 分不通过；本模块为 `draft`。
> 注意：舆情模块的"完整"不等于"条数多"，而是关键事件被识别且强度标注正确。

## 1. 事实准确性

| 分 | 判据 |
|---|---|
| 5 | 事件时间、主体、经过与原始页面一致；五级信息强度（已裁定/指控/自述/媒体/匿名）标注正确；无一处把匿名帖当事实 |
| 3 | 主要事件正确，个别时间点（首发/回应）只有月份，已说明 |
| 1–2 | 把传闻写成事实；把"涉嫌"写成"已认定"；事件主体张冠李戴 |

## 2. 引用准确性

| 分 | 判据 |
|---|---|
| 5 | 每条事件有可打开的原始页面，locator 到段落；公司回应为原文引用 |
| 3 | 主要事件有链接，个别只有搜索结果摘要并已标注 |
| 1–2 | 事件无链接；引用打不开；用二次转述替代原文 |

## 3. 完整性

| 分 | 判据 |
|---|---|
| 5 | 负面事件、举报投诉、利益相关方、整体口碑四类齐全；每条事件有后续进展；单源已标注 |
| 3 | 三类有结论，缺项写了 `not_disclosed_after_search` 与检索记录 |
| 1–2 | 只列了几个标题，无时间、无后续、无回应 |

## 4. 来源质量

| 分 | 判据 |
|---|---|
| 5 | 优先法院公告、监管通报、公司公告；媒体报道取首发源；匿名舆情只作线索并标注 |
| 3 | 主要依赖权威媒体，匿名信息已隔离标注 |
| 1–2 | 以自媒体、匿名帖为主；把转载当独立源 |

## 5. 对账

| 分 | 判据 |
|---|---|
| 5 | 与 `legal.risk` 的诉讼事件一致（同一事件不重复计数）；与 `org.people` 的人员一致；与 `regulatory-compliance` 的处罚一致 |
| 3 | 有 1 处表述差异（如同一事件的日期口径）且已说明 |
| 1–2 | 同一事件在两模块状态矛盾未标 `conflict`；关键人姓名或职务不一致 |

## 记录要求

- 每条扣分写：维度、事件（标题或 `data.incidents[i]`）、理由、需补证据；
- 舆情"负面"不是扣分项，标注不清才是；
- 复核人只能提修订，不得自行改为 `verified`。
