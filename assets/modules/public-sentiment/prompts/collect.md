# {{module.name}} · 采集任务：舆情与利益相关方

## 任务

对 **{{company.name}}**（代码 {{company.code}}）检索近 {{params.daysBack}} 天的负面事件、举报投诉、利益相关方评价与后续进展。
委托方：{{project.client}}；模块：{{module.name}}；分区：{{unit.partition}}。
产出底稿 `public.sentiment`，只记录事件与来源强度，不写情绪判断。

## 输入

- 关键人（用于人物相关检索）：{{artifact:org.people}}
- 业务与产品（用于质量类检索词）：{{artifact:business.segment}}
- 司法风险（软引用，避免与诉讼重复）：{{artifact:legal.risk}}

## 参数

- 回溯天数：{{params.daysBack}} 天（窗口外仍在发酵的事件必须收录）
- 剩余预算：{{budget.remaining}}

## 必答问题（每条落到 `data` 或 `openQuestions`）

1. 时间窗内最主要的 3 个负面事件是什么？首发时间、传播路径、后续进展？
2. 有没有实名举报、集体投诉、监管立案或媒体调查报道？
3. 公司是否回应？回应时间与内容？之后事件是平息还是升级？
4. 员工、客户、供应商、周边居民、监管、投资人分别有什么公开表态？
5. 整体口碑在该时间窗内是改善、恶化还是平稳？依据是什么？
6. 哪些信息是已裁定事实、哪些是指控、哪些只是匿名帖？

## 检索词起点

- `"<公司全称>" 投诉` / `"<公司全称>" 质量` / `"<公司全称>" 维权`
- `"<公司全称>" 欠薪` / `"<公司全称>" 裁员` / `"<公司全称>" 举报`
- `"<公司全称>" 造假` / `"<公司全称>" 做空` / `"<公司全称>" 声明`
- `"<关键人姓名>" 负面` / `"<关键人姓名>" 纠纷`

## 检索路径（按序执行）

1. 综合搜索（百度/必应/谷歌）公司名 + 关键词，记录检索日期与前几页；
2. 财经媒体站内检索与公司名标签页；
3. 黑猫投诉、12315 公示、消费维权平台；
4. 微信公众号文章（搜狗微信或站内搜索）；
5. 人民法院公告网与地方法院开庭公告；
6. 公司官网新闻中心与公告中的"澄清/说明"。

## 输出字段清单

- `data.incidents[]`：date / title / summary / sourceTier / status / note
- `data.sentiment[]`：period / tone / summary / note
- `data.stakeholders[]`：party / stance / note

## 口径要求

- `incidents.status` 用：发酵中 / 已回应 / 已和解 / 已判决 / 已平息 / unknown；
- `sentiment.tone` 用：正面 / 中性 / 负面，note 写样本量与时间窗；
- `stakeholders.party` 用：员工 / 客户 / 供应商 / 周边居民 / 监管 / 投资人 / 合作伙伴；`stance` 用：支持 / 中立 / 反对 / 未知；
- 每条事件写"发生时间 → 首次曝光 → 当事人回应 → 最新进展"四个时间点；
- 必须区分五级信息强度：已裁定事实 / 监管指控 / 企业自述 / 媒体报道 / 匿名舆情。

## 六态写法

- 只有搜索结果标题、打不开原文：`not_disclosed_after_search` + 说明；
- 只知道"多条投诉"：`lower_bound` + 已知条数；
- 需公司投诉台账/和解协议：`pending_dd`；
- 公司与投诉方说法矛盾：`conflict` + 两方陈述；
- 无面向消费者的业务：`not_applicable` + 依据；
- 舆情热度/口碑倾向：可 `estimated`，必须带 `derivation`；事件事实不得 estimated。

## 不要做

- 不把匿名帖、员工爆料当事实；
- 不把单条投诉当系统性质量事故；
- 不把转载当双源；
- 不用情绪化词汇给公司或个人定性；
- 不采集个人身份信息，不做人身评价；
- 不给舆情处置建议；
- 不声称已核验或专家已审。
