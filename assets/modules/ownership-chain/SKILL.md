# 股权、控制权与特殊权利（ownership-chain）

> 模块状态：`draft`。方法论可执行、有门与 rubric，**尚未经过金融专家评审**。
> 不得在交付物中标注 `stable` 或“专家已审”。

## 1. 一句话目标

把目标公司（`company.identity` 已确认的主体）的**股权层级、控制关系、特殊权利与历次变更**
写成一份可逐层复核的 `ownership.chain` 底稿，并在这里给出**控制权结论**。

本模块回答五个问题：

1. 现在谁持股、持多少、直接还是间接？
2. 逐层穿透到最终自然人/国资/外资主体，一共几层？
3. 谁是控股股东、实际控制人，控制基础是什么？
4. 有没有一致行动、表决权委托、特殊权利安排？
5. 历史上股权怎么变过来的，控制权是否发生过变更？

### 1.1 控制结论的唯一出口

- 控制权（控股股东、实际控制人、控制基础、控制稳定性）**只在本模块出结论**。
- `entity-resolution` 里的 `controllingPerson` 只是**线索**，不得与本模块结论并列展示。
- 下游报告、摘要、红旗清单引用控制结论时，必须指向本模块的 `control[]`。

### 1.2 本模块不做

- 不做主体核名（已由 `entity-resolution` 完成）。
- 不做对外投资平台与被投实体枚举（`investment-map`）。
- 不做财务、诉讼、合规判断（分别归各自模块）。
- 不推断未披露的持股比例，不用同行结构替代本公司结构。

## 2. 输入与前置

| 输入/参数 | 必要性 | 缺失时的处理 |
|---|---|---|
| `company.identity` | 必须（`onMissing: block`） | 不启动；先补主体识别 |
| `{{params.maxLayers}}` | 默认 8，范围 2–15 | 超过上限的层级必须标 `pending_dd` 并说明停在哪一层 |
| `{{params.includeSpecialRights}}` | 默认 true | 为 false 时 `specialRights` 写 `not_reviewed` 并在 `notes` 说明 |
| `company.history` | 软引用 | 缺失只警告；历史变更以工商变更记录与公告为准 |
| `org.people` | 软引用 | 缺失时人物身份只写公开披露口径，不推断亲属关系 |

## 3. 穿透方法

### 3.1 逐层记录

- 一层 = 一个 `holder → subject` 的持股关系，写入 `layers[]`：`level`、`holder`、`subject`、`pct`、`basis`、`note`。
- `level=1` 是目标公司的直接股东；`level=2` 是股东的股东，以此类推。
- 每一层都要写 `basis`（口径）：`直接`、`间接`、`穿透`、`表决权`、`名义持有`、`代持（未证实）`。
- 每层 `pct` 是**该层持股比例**，不是累计比例；累计比例放 `capTable[].totalPct`。
- 到达自然人、国资委/政府平台、上市公司、境外注册主体或无法再查的层级即停止，并写明停因。
- 员工持股平台、信托、资管计划、契约型基金要单列，不得当作普通法人股东混入。

### 3.2 直接 + 间接

- `capTable[]` 一行一个最终持有人：`directPct`（直接）、`indirectPct`（经平台/基金间接）、`totalPct`（合计）。
- `totalPct = directPct + indirectPct`；间接比例按各层比例**相乘**得到，写明计算路径。
- 同一持有人通过多条路径持股时，各路径分别列出再求和，不得只取最大路径。
- 合计应≈100%；差额来自未披露股东、库存股、员工持股平台或境外层，必须在 `note` 说明。
- 差额超过 1 个百分点时，`consistency` 判失败，需补查或标 `not_disclosed_after_search`。

### 3.3 口径标注（强制）

每条比例至少标注四项：

1. **直接/间接/穿透**：这个数是怎么算出来的。
2. **股权/表决权**：经济比例还是表决权比例，两者不同时分别记录。
3. **母公司/合并**：单体口径还是并表口径。
4. **截至日**：`asOfLabel` 与 `asOf` 一致，历史比例写对应日期。

其他口径：是否含员工持股平台、是否含未行权期权/可转债、是否含一致行动人合计。

## 4. 一致行动与控制结论

### 4.1 一致行动

- 来源优先级：权益变动公告/收购报告书/招股书 > 工商登记 > 媒体。
- 形式：一致行动协议、表决权委托、家族关系、同一控制人、董监高兼任。
- 每条写清：主体、依据（协议/亲属/控制）、覆盖比例、期限、是否已解除。
- 亲属关系必须由可靠来源明确表述；没有表述的写“疑似，未证实”，不得推定。
- 一致行动合计比例要与单人比例分列，不得把合计写成某一个人的持股。

### 4.2 控制结论（`control[]`）

每行至少包含：

- `name`：控股股东或实际控制人（自然人写姓名，法人写全称）。
- `role`：`控股股东` / `实际控制人` / `共同实际控制人` / `无实际控制人`。
- `basis`：`股权` / `表决权` / `协议控制` / `董事会席位` / `章程特别条款`。
- `note`：认定依据、口径、与 identity 线索的差异。
- `status`：六态之一；无实际控制人也要写 `found` 并说明依据（如股权分散、无一致行动）。

判断顺序：

1. 先看公告是否明确披露“控股股东/实际控制人”；
2. 再看直接+间接合计表决权是否形成控制；
3. 再看协议控制、董事会席位、章程条款；
4. 都没有 → 写“无实际控制人”或 `not_disclosed_after_search`，不硬凑。

### 4.3 控制稳定性

- 近三年是否发生控制权变更；是否有一致行动解除、股权质押、表决权委托到期。
- 控制稳定性只做事实描述与风险提示，不下“控制权不稳”的定性结论。
- 质押/冻结等风险事实交 `red-flags` 的触发器处理，本模块只提供输入。

## 5. 特殊权利（`specialRights[]`）

必查类型：

- 一票否决/重大事项同意权；
- 优先认购权、优先购买权、共同出售权；
- 优先清算权、回购/赎回权、对赌/业绩补偿；
- 董事提名权、观察员席位；
- 反稀释、最惠待遇、信息权与检查权；
- 领售权/拖售权、上市承诺与赎回触发。

每条写清：`type`、`holder`、`terms`（期限、触发条件、价格公式，能摘原文就摘）、
`sourceIds`（对应 evidence）、`status`（`found`/`not_disclosed_after_search`/`pending_dd`）。

注意：

- 已解除或已到期的条款要标注“已解除/已到期”，不得当作现存权利。
- 只在公司章程、投资协议、招股书特别表决权章节中出现；公开信息查不到时写 `pending_dd`。
- 特殊权利的存在不等于控制权变化，两者分开写。

## 6. 历次变更（`history[]`）

- 事件类型：设立、增资、股权转让、改制、股改、员工持股、引入战投、控制权变更、境外重组、分立/合并、减资。
- 每条写：`date`、`event`、`detail`（前后比例、对价与币种、交易对方）、`sourceIds`。
- 变更前后比例要对得上：本次变更后的 `capTable` 应能解释历史差异。
- 早期变更无公开记录的写 `not_reviewed` 或 `not_disclosed_after_search`，不得用“推测”补齐。
- 控制权变更事件必须与 `control[]` 的现状结论一致；不一致时在 `openQuestions` 说明。

## 7. 检索计划

### 7.1 来源优先级

| 级别 | 来源 | 用途 |
|---|---|---|
| A | 权益变动公告、收购报告书、招股书、年报、公司章程 | 股东名单、比例、实控人、一致行动、特殊权利 |
| B | 国家企业信用信息公示系统、工商快照、中基协备案 | 股东结构、出资、变更记录、合伙企业合伙人 |
| C | 交易所问询回复、评级报告、权威媒体 | 补充与交叉 |
| D | 一般媒体、传闻 | 只作线索 |

### 7.2 检索词

- `[目标名] 股东 持股比例`
- `[目标名] 实际控制人 公告`
- `[目标名] 一致行动人`
- `[目标名] 权益变动报告书`
- `[目标名] 公司章程 特别表决权`
- `[目标名] 增资 股权转让 历史沿革`
- `[股东名] 合伙人 出资`（合伙企业股东）
- 英文：`[英文名] shareholder structure`、`[英文名] beneficial ownership`

### 7.3 检索顺序

1. 最新公告/年报的股东名单与实控人表述；
2. 工商登记的股东与出资；
3. 合伙企业股东的合伙人名单（逐层）；
4. 历史公告与工商变更记录；
5. 招股书/问询回复中的特殊权利与对赌条款；
6. 媒体线索回查 A/B 级。

## 8. 字段与口径

| 字段 | 说明 | 六态边界 |
|---|---|---|
| `data.asOfLabel` | 口径标签，如“截至 YYYY-MM-DD，合并口径” | 必填 |
| `data.capTable[]` | 最终持有人表，`directPct`/`indirectPct`/`totalPct` | 合计≈100%；差额写 note |
| `data.layers[]` | 逐层持股关系 | 至少 1 层；未穿透到底写停因 |
| `data.ubo[]` | 最终受益所有人，`pct`/`basis`/`confidence` | 无法识别 → `not_disclosed_after_search` |
| `data.control[]` | 控制结论 | 每行带 `status` 与 `note` 说明 |
| `data.specialRights[]` | 特殊权利 | 查不到 → `pending_dd`/`not_disclosed_after_search` |
| `data.history[]` | 历次变更 | 早期无记录 → `not_reviewed` |

`ubo` 与 `control` 的区别：`ubo` 是受益所有人（经济利益），`control` 是控制权（表决权/协议）。
两者可以是不同主体，必须分开写，不得合并成一行。

## 9. 六态与边界

- `found`：公告或工商明确披露，且与另一来源一致。
- `not_disclosed_after_search`：写清查过的库、词、日期与筛选，能对上 `search.ledger`。
- `lower_bound`：只用于“至少 X 层/至少 X 名股东”类事实。
- `pending_dd`：需章程、投资协议、合伙协议、员工持股方案才能确认。
- `conflict`：公告与工商不一致（常见于股比、实控人表述），保留候选与裁决。
- `not_applicable`：单一股东全资子公司无“其他股东”口径时可标。
- `not_reviewed`：未查或预算耗尽，不得伪装成已查。
- `estimated` 本模块禁用（`gates.maxEstimatedRatio=0`）；穿透比例是计算，不是估算。
- 公司特定事实（第一大股东、前五大合计、股东数）不得用同行均值替代。

## 10. 常见误判

1. **把持股平台的 GP 当实控人**：GP 可能只是执行事务合伙人，控制权要看协议与份额。
2. **漏算一致行动**：只看单人比例会低估控制力；一致行动合计要单列。
3. **把表决权比例当经济比例**：AB 股、表决权委托、一致行动都会让两者分离。
4. **穿透中断不标注**：停在 BVI/信托层却不写停因，读者会误以为已穿透到底。
5. **合计不到 100% 硬凑**：差额是信息，不是错误；写清差额来源比凑数更重要。
6. **用旧工商快照**：股权变更加工频繁，快照必须标日期，必要时以公告为准。
7. **把已解除对赌当现存**：特殊权利要标状态与解除时间。
8. **把子公司当股东层**：子公司是投资对象，不是目标公司的股东，方向不能反。
9. **红筹层层 BVI 未穿透**：境外层常无公开登记，必须写 `pending_dd`。
10. **把“无实际控制人”写成“未查到”**：两者含义不同，前者是结论，后者是缺口。

## 11. 验收要点

- `layers` 至少 1 层，且能画出从目标公司到最终持有人的完整路径。
- `capTable` 合计在 99%–101% 之间，或 `note` 明确解释差额来源。
- `control` 有明确 `basis`，无实际控制人时给出依据。
- `specialRights` 每条有 `sourceIds` 或六态说明；已解除条款有状态标注。
- `history` 覆盖近三年重大变更；控制权变更与现状结论一致。
- 每条 material claim 至少一条 `role=supports` 证据。
- 不出现 `estimated`；无同行均值替代。

## 12. 与其他模块的关系

- 上游：`company.identity`（硬依赖）。
- 下游：`investment-map`（平台归属判断）、`red-flags`（质押/控制权触发器）、`deliverable`（摘要与工作簿）。
- 软引用：`company.history`、`org.people`、`financials.public`。
- 控制结论的唯一来源是本模块；其他模块只能引用，不得另出结论。

## 13. 已知缺口（draft 阶段）

- 未上市公司的股东名单常只能拿到工商快照，穿透深度受数据源限制。
- 合伙企业多层嵌套时，合伙人名单可能只在部分层级公开。
- 特殊权利条款多在不公开的投资协议中，公开渠道只能拿到招股书披露的片段。
- 一致行动中的亲属关系依赖明确表述，公开信息不足时只能标“疑似，未证实”。
