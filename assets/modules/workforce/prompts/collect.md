# {{module.name}} · 采集任务：组织、人力与用工

## 任务

对 **{{company.name}}**（代码 {{company.code}}）梳理人数、结构、人效、社保合规与招聘趋势。
委托方：{{project.client}}；模块：{{module.name}}；分区：{{unit.partition}}。
产出底稿 `workforce.profile`，只用公开信息，不做投资判断。

## 输入

- 主体识别：{{artifact:company.identity}}
- 财务（软引用，用于人效与人均薪酬）：{{artifact:financials.public}}

## 参数

- 回溯年限：{{params.yearsBack}} 年
- 剩余预算：{{budget.remaining}}

## 必答问题（每条落到 `data` 或 `openQuestions`）

1. 最近一期在职员工总数是多少？口径（期末/平均、合并/母公司）与时点？
2. 职能、学历、地域、产线结构如何？研发人员占比多少？
3. 工商年报的社保参保人数是多少？五险分项是否一致？与在职人数差多少、为什么？
4. 人均营收、人均净利、人均薪酬分别是多少，近三年趋势？
5. 当前在招什么岗位、在哪些城市？扩张还是收缩？
6. 近三年有无劳动争议、欠薪、工伤、社保稽核或补缴？

## 检索词起点

- `"<公司全称>" 员工人数` / `"<公司全称>" 研发人员 占比` / `"<公司全称>" 劳务派遣`
- `"<公司全称>" 社保 参保人数` / `"<公司全称>" 公积金 缴纳` / `"<公司全称>" 社保 稽核`
- `"<公司全称>" 人均创收` / `"<公司全称>" 人均薪酬`
- `"<公司全称>" 劳动争议` / `"<公司全称>" 欠薪` / `"<公司全称>" 招聘 <城市>`

## 检索路径（按序执行）

1. 最近 {{params.yearsBack}} 期年报"员工情况"：人数、专业构成、教育程度、劳务外包；
2. 国家企业信用信息公示系统历年年报的"社保信息"栏（五险分项参保人数）；
3. 招股说明书/募集说明书"员工与社会保障"章节（派遣比例、补缴风险）；
4. 复用 `financials.public` 的营业收入与应付职工薪酬，算人效与人均薪酬；
5. 招聘平台按公司名检索在招岗位，记录抓取日期、城市、岗位类别；
6. 中国裁判文书网"劳动争议/追索劳动报酬/工伤保险待遇"案由检索。

## 输出字段清单

- `data.headcount`（数字，带 note 说明口径与时点）
- `data.structure[]`：kind / count / pct
- `data.socialInsurance`（数字）+ `data.socialInsuranceNote`
- `data.employeeCost`：amount / currency / unit / note
- `data.hiring[]`：role / location / count / note（含抓取日期）
- `data.laborDisputes[]`：案由、时间、金额、状态

## 六态写法

- 人数只有模糊表述：`lower_bound` + 已知下限；
- 社保只有"依法缴纳"文字：`not_disclosed_after_search` + 查过的库与词；
- 需工资表/缴费明细才能判断：`pending_dd` + 说明要什么；
- 年报人数与工商从业人数差异大：`conflict` + 两个值；
- 人效/人均薪酬：可 `estimated`，但必须带 `derivation`（算法、输入、假设）；
- 人数、参保人数一律不得 `estimated`，不得用同行均值。

## 不要做

- 不采集员工个人姓名、工号、薪酬明细、身份信息；
- 不把"员工总数 − 参保人数"直接定义为"未缴社保"；
- 不把招聘岗位数当成实际招聘人数；
- 不把员工社区帖子当成劳资纠纷事实；
- 不声称已核验或专家已审。
