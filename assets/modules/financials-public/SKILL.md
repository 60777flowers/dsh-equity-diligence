# financials-public · 财务质量与勾稽

> 模块状态：**draft**。方法论未经金融专家评审，不得声称 `stable` 或"专家已审"。
> 输出底稿：`financials.public`（scope=company，cardinality=**many**，partitionKey=财年，如 `FY2025`）。
> 一句话目标：把公开财报变成"能对账的数字表"，而不是一段文字结论。

## 1. 回答什么问题

1. 这个财年公司赚了多少、赚得干不干净（收入、毛利、净利、经营现金流）？
2. 三张表能不能对上（资产=负债+权益、现金、净利润、毛利）？
3. 会计口径是什么：准则、币种、单位、合并范围、期间、原始还是重述？
4. 审计意见是什么类型，有没有强调事项、关键审计事项、持续经营提示？
5. 收入与现金流、应收、存货、关联交易之间的关系是否异常？
6. 纳税信用、海关信用、用电等外部数据能不能旁证收入与产能？

## 2. 输入、前置与降级

| 关系 | 类型 | 说明 |
|---|---|---|
| 硬输入 | `business.segment` | 提供产品/分部/收入结构，决定收入拆分口径 |
| 软引用 | `valuechain.parties` | 客户/供应商集中度，用于收入质量与关联交易判断 |
| 软引用 | `supply.capacity` | 产能与产量，用于收入与用电的合理性交叉 |

- 降级：无 `business.segment` 时不得启动（block）；无客户/产能数据时，收入质量只做表内分析并标 `pending_dd`。
- 分区：**一个财年一个 artifact**，`{{unit.partition}}` = `FY2025` 这类财年键；跨年趋势由下游读取多个分区，不在单分区里塞多年数据。
- 期间非整年的（如港股中期、美股财年），partitionKey 用 `FY2025H1` 这类可排序键，并在 `data.periodNote` 写起止日。

### 3.4 必查库与必开页面

- 巨潮资讯网与各交易所：年报全文 PDF（正文 + 财务报表 + 附注）、审计报告、非经常性损益明细；
- 上交所/深交所/北交所发行上市审核网站：招股书与审核问询回复；
- 中国证监会及地方证监局：行政处罚、监管措施、会计监管提示；
- 全国纳税信用等级查询（省级税务局公示）与海关企业信用信息公示；
- 全国排污许可证管理信息平台/地方用电数据（如有公开），仅作旁证。

### 3.5 检索顺序与预算

1. 定位年报并下载全文（约 3 次）；
2. 抽取三表主要科目与附注关键项（约 8 次）；
3. 审计意见与关键审计事项（约 2 次）；
4. 口径与重述检查（约 3 次）；
5. 勾稽核算与异常项回查（约 6 次）；
6. 外部旁证（纳税/海关/用电，约 4 次）。
上限见 `module.yaml` 的 `budget.toolCallsPerUnit=26`；超预算优先保三表与勾稽，旁证降级为 `pending_dd`。

## 4. 字段与口径

| 字段 | 结构 | 定义 | 算 `found` | 算 `not_disclosed_after_search` |
|---|---|---|---|---|
| `data.fiscalYear` | string（必填） | 财年键，如 `FY2025` | 与报告期一致 | — |
| `data.currency` | string | 报表币种（CNY/USD/HKD…） | 报表首页或附注声明 | 只能从单位推断时标 `pending_dd` |
| `data.accountingStandard` | string | CAS / IFRS / US GAAP | 附注"编制基础"明确 | 未披露 |
| `data.auditOpinion` | string | 审计意见类型 | 审计报告原文 | 未经审计（如季报）写 `not_applicable` |
| `data.consolidation` | string | 合并范围说明 | 附注"合并范围"章节 | 未披露 |
| `data.revenue` | `amount`/`currency`/`unit`/`note` | 营业收入 | 利润表金额 | 未披露 |
| `data.netProfit` | 同上 | 归母净利润（须在 note 写明"归母"或"净利润"） | 利润表金额 | 未披露 |
| `data.grossMargin` | number | 毛利率（0–1 小数） | 可算或直接披露 | 营业成本未披露 |
| `data.statements` | object | 三表摘要（资产负债表、利润表、现金流量表关键行） | 逐项有数 | 缺表 |
| `data.recon[]` | `check`/`left`/`right`/`status`/`note` | 勾稽结果 | 已算并给两值 | 缺一表无法算 |

- `data.grossMargin` 用小数（0.35 表示 35%），不要写字符串；单位在 `revenue.unit` 写清（元/万元/百万元）。
- `data.statements` 至少包含：总资产、总负债、所有者权益、货币资金、应收账款、存货、营业收入、营业成本、净利润、经营活动现金流净额、投资活动现金流净额、筹资活动现金流净额、期末现金及现金等价物。

### 4.1 会计口径

必须写清五要素：准则（CAS/IFRS/US GAAP）、币种、金额单位、合并口径（合并/母公司）、期间（起止日）。缺任一项，`data.currency` 或 `data.consolidation` 标 `pending_dd`，不得默认人民币或合并。

### 4.2 审计意见

六类：标准无保留、带强调事项段的无保留、保留意见、否定意见、无法表示意见、未经审计。必须抄录意见段原文片段；带持续经营重大不确定性段落的，必须在 `flags` 记 `attention` 或 `material`（只写核查动作，不定性）。

### 4.3 原始与重述

同一财年出现两个版本时：优先取**最新重述后**数据，同时保留原始值；`data.statementNote` 写"原始/重述 + 差异原因 + 公告日期"。重述原因的检索词：会计政策变更、前期差错更正、同一控制下企业合并追溯调整、并购重组追溯。

### 4.4 合并范围

合并范围变化会让同比失真。必须查：本期新增/减少子公司、处置、同一控制下合并、结构化主体。合并范围变化未披露而同比异常时，`data.consolidation` 标 `pending_dd` 并在 `flags` 记 `attention`。

### 4.5 三表勾稽（必须逐条计算并写入 `data.recon`）

1. 资产 = 负债 + 所有者权益（容差按报表单位取整）；
2. 现金流量表期末现金及现金等价物 = 资产负债表货币资金 − 受限资金（受限资金在附注"所有权受限"查）；
3. 现金流量表补充资料"净利润" = 利润表净利润；
4. 营业收入 − 营业成本 = 毛利；毛利 / 营业收入 = `grossMargin`；
5. 未分配利润期末 = 期初 + 本期净利润 − 分配（有分红时）；
6. 经营现金流净额与净利润的方向性差异（连续两年背离写 `attention`）；
7. 应收账款增速 vs 收入增速、存货增速 vs 成本增速（异常写 `attention`）。

每条 recon 必须同时给 `left`、`right` 和 `status`（`pass`/`fail`/`insufficient`）。`insufficient` 表示缺表或缺科目，不是"通过"。

### 4.6 收入质量

看四组关系：收入与经营现金流、收入与应收账款、收入与存货、收入与关联交易。任一组连续两年反向，写 `flags`（`attention`）并列出需核项（收入确认时点、验收单、关联方非关联化）。不得直接写"虚增收入"。

### 4.7 外部旁证

- 纳税信用等级（A/B/M/C/D）：只作旁证，权威记录在 `regulatory-compliance`；
- 海关信用（高级认证/失信）：只作旁证；
- 用电量/能耗：多数不公开，查不到写 `pending_dd`，不得用行业单位电耗反推收入；
- 银行授信、评级报告里的财务数据：可作第三方复核源，但以公司公告为准。

## 5. 六态与边界

- `found`：报表或附注可读到数字；
- `not_disclosed_after_search`：查过年报、招股书、问询回复仍无；
- `lower_bound`：只披露区间或"不低于"；
- `pending_dd`：需要审计底稿、明细账、纳税申报表、用电单据；
- `conflict`：原始与重述、公告与终端数据不一致，保留两组值；
- `not_applicable`：未审计期间、无该项业务；
- `not_reviewed`：本轮未查；
- `estimated`：仅允许用于分析型派生值（如可比毛利率区间），必须带 `derivation`；报表科目一律不得 estimated。

边界：不做盈利预测，不给估值，不判断"财务造假"；只写"勾稽不通过/异常/需核"。公司特定财务数字禁止用同行均值替代。

## 6. 常见误判

1. 把"营业收入"与"营业总收入"、"净利润"与"归母净利润"混用。
2. 用合并报表收入除以母公司人数算人效。
3. 把终端数据库数字当原始披露（终端会做重述与调整）。
4. 忽略金额单位（元/万元/百万元），导致差 100 倍。
5. 用未经审计的季度数据做年度结论。
6. 把"非经常性损益"（政府补助、资产处置）当主营利润。
7. 勾稽时直接用货币资金对期末现金，忽略受限资金。
8. 同一财年同时引用重述前后两个数字而不说明。
9. 把"审计意见带强调事项段"写成"保留意见"。

## 7. 验收要点

- 证据：≥6 条；三表关键科目各至少 1 条 supports；审计意见必须原文引用；
- 覆盖：收入、净利、毛利率、三表摘要、审计意见、口径六项齐全；
- 勾稽：`data.recon` ≥3 条，每条有 left/right/status；
- 必答：①本财年收入与归母净利；②毛利率及算法；③审计意见类型；④合并范围是否变化；⑤经营现金流与净利是否背离；⑥是否发生重述；
- 一致性：`grossMargin` 与 recon 第 4 条可复算；`revenue.amount` 与 `statements` 中营业收入一致。

## 8. 与其他模块的关系

- 上游（硬）：`business.segment`；软引用 `valuechain.parties`、`supply.capacity`；
- 下游：`debt-guarantee`（有息负债与偿债指标）、`assessment-fit`（估值与投入能力）、`red-flags`、`deliverable`（财务页）；
- 不重复：纳税信用与海关信用的权威记录归 `regulatory-compliance`；有息负债明细归 `debt-guarantee`；人数与人效归 `workforce`。

## 9. 交付前自检

- [ ] 每个数字有单位、币种、期间、口径
- [ ] `recon` 每条都有 left/right/status，没有"通过"式空话
- [ ] 审计意见抄了原文
- [ ] 重述与合并范围变化有说明
- [ ] 没有任何"虚增/造假/造假嫌疑"式定性
- [ ] 全文无 `stable`、`已审` 字样

## 10. 明确不覆盖

- 盈利预测与估值模型；
- 税务合规的实质判断（只记纳税信用等级与公开处罚线索）；
- 有息负债结构与担保明细（归 `debt-guarantee`）；
- 内控审计意见的实质评价；
- 未公开的管理层报表、成本明细、客户合同。
