# 未 stable 方向的最低调查清单 · 产品矩阵与技术路线

> 用途：预算不足或上游未 verified 时的最小可交付集合。不降低证据与六态要求。

## 1. 最低必查

1. **产品清单**：从招股书"主要产品"或官网产品中心取到 ≥1 个产品的名称、用途、是否在售。
2. **代际**：至少对主力产品给出代次，并记录原文表述；无代次则写 `not_disclosed_after_search`。
3. **收入构成**：取最近一个完整年度的分产品（或分行业）占比，标注期间与口径；能取金额优先取金额。
4. **技术路线**：至少一条核心路线 + 阶段（量产/验证/研发/规划）。
5. **扩产周期**：至少给一个区间或明确写"未披露且已检索哪些来源"。

## 2. 最低可交付字段

| 字段 | 最低要求 | 不满足时 |
|---|---|---|
| `data.products[]` | ≥1 行，含 name/category/generation | 无产品信息 → 整模块 `not_reviewed` + openQuestions |
| `data.revenueMix[]` | ≥1 组，合计 100%±1pp（如只披露一项则写 100 并注"仅单一产品"） | 无收入拆分 → `not_disclosed_after_search`，不得估 |
| `data.segments[]` | 可为空数组，但需说明披露口径 | 空且无说明 → 门不过 |
| `data.techRoute[]` | ≥1 行，含 route 与 status | 无 → `not_disclosed_after_search` |
| `claims` | ≥3 条，其中 ≥1 条 material | 证据不足 → 门不过 |

## 3. 必须标注的缺口

- 分产品收入金额（多数公司只披露占比）。
- 单产品毛利率、单产品成本结构。
- 未上市产品的路线图与量产时间表。
- 客户认证阶段（与 `customers-orders` 共享缺口）。
- 若只有年报无招股书：产品型号粒度、代际定义、技术路线细节。

## 4. 禁止的凑数做法

- 用行业平均产品结构代替公司收入构成。
- 用研报拆分表覆盖公司披露口径。
- 把下游应用、制程节点、型号后缀当产品代际。
- 把"预计/规划"写成已量产。
- 用 `estimated` 覆盖整组收入构成而不写 derivation。
