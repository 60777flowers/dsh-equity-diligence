# 审核 rubric · 产品矩阵与技术路线（business-segment）

> 模块状态：**draft**，未经过金融专家评审。
> 评分对象：单个 `business.segment` 底稿。五维各 1–5 分，**任一维 ≤2 即整体不通过**。

## 1. 五维评分表

| 维度 | 1 分 | 2 分 | 3 分（及格线） | 4 分 | 5 分 |
|---|---|---|---|---|---|
| **事实准确性** | 产品/代际与来源不符，或凭空造产品线 | 代际或收入构成多处与原文不一致 | 主要产品、代际、收入构成与公司披露一致；口径已标注 | 每个产品可回到具体章节/表格，代际与制程分开写 | 逐项可回溯；公司口径与研报口径冲突时保留候选并说明取舍 |
| **引用准确性** | 引文不存在 | 引文为改写，locator 缺失 | 引文为原文片段，到章节/页码 | 每条 material claim 有 supports 证据 | 关键代际/占比有双源（招股书+年报或官网），独立源已核 |
| **完整性** | 只有产品名，无收入与技术路线 | 缺收入构成或技术路线其一 | 产品、收入构成、技术路线、扩产周期四块均有覆盖 | 分产品/分行业/分地区三口径尽量齐，缺口写六态 | 三代以上产品代际齐全、收入可拆到单产品、路线阶段有来源、扩产周期可对上募投 |
| **来源质量** | 仅研报/媒体 | 以官网自述为主 | 招股书/年报为主，官网为辅 | 定期报告 + 问询回复 + 标准文档 | 一手披露 + 标准组织/专利交叉，且注明各源权威性 |
| **对账** | 收入合计严重偏离且未解释 | 合计偏离 >1pp 无说明 | `revenueMix` 同口径合计 100%±1pp，与 `segments` 对得上 | 与 `financials.public` 营业收入、毛利率可对账 | 收入结构在底稿、财务底稿、交付表三处完全一致，差异有 `conflictGroup` |

## 2. 3 分与 5 分的判据

**3 分**
- `products[]` 至少覆盖主要产品/系列，每个有 `name` 与 `generation`（或六态 + note）。
- `revenueMix[]` 同期间同口径合计 100%±1pp；若公司只披露分行业，`segments[]` 已承接并标注口径。
- `techRoute[]` 至少一条路线有阶段，阶段与来源不矛盾。
- 扩产周期至少对主要产品给出区间或 `not_disclosed_after_search`。

**5 分**
- 产品矩阵按代际成序列（第 1 代→第 N 代），每代有来源与上市时间；代际与制程/型号后缀明确区分。
- 收入构成同时给出金额与占比，金额能加总回营业收入（差额有说明）；分产品与分行业两套口径并列不混算。
- 技术路线与产品一一对应（哪条路线支撑哪个产品），阶段证据来自公告/问询回复/标准文档。
- 扩产周期能对上募投项目或环评的产能与达产时间，并与 `supply-capacity` 的产能口径一致。

## 3. 门与一致性判定（本模块）

| 门/规则 | 含义 | 不过的处理 |
|---|---|---|
| `minEvidence: 3` | 证据 ≥3 条 | 判 2 分（引用准确性） |
| `minCoverage: 0.8` | 必答问题覆盖 ≥80% | 判 2 分（完整性） |
| `minItems.data.products / revenueMix ≥1` | 不得为空 | 空即 `block`，插 `not_applicable` 行需说明 |
| `sixStateFields` | 代际、产品状态、路线状态、分部毛利率必须能落六态 | 空白即判 2 分 |
| `maxEstimatedRatio: 0.2` | 估算字段 ≤20% | 超限判 2 分，要求改 `pending_dd` |
| `revenue-mix-sum` | 同期间合计 100%±1 | `block` |
| `revenue-mix-range` | 占比 0–100 | `block` |
| `product-name-unique` | 产品名不重复 | `block`，合并同义名 |
| `segment-vs-mix` | 分部占比与收入构成对账 ±1pp | `attention`，写 note |

六态行级写法：对 schema 中带类型的标量字段（如 `segments[].grossMargin`、`revenuePct`），六态写在**该行 `note` 的开头**（`found｜…`、`pending_dd｜…`）；对无类型字段（如 `products[].generation`），可直接写 `{status, value, note}` 对象。两种写法都必须能被门解析。

一致性 `kind` 语义（本模块用到）：`sum` 按 `groupBy` 分组求和；`range` 数值区间；`unique` 字段唯一；`cross_check` 两组数值按分组对账。`onFail=block` 返工，`attention` 记录。

## 4. 一票否决项

1. 编造产品型号、代际、收入占比或 URL。
2. 把下游应用/行业写成产品线，或把制程节点写成产品代际。
3. 用同行产品结构或行业平均替代本公司收入构成。
4. 把"规划/预计"写成"量产/已上市"。
5. 声称本模块 `stable` 或"专家已审"。
