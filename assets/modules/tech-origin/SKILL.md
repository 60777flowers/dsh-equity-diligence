# 技术来源、许可与 FTO 线索（tech-origin）

> 模块 id：`builtin/tech-origin` ｜ kind：`verify`（核验类，不是简单收集）｜ 状态：**draft**（未经金融专家评审，不得称为 stable）
> 输出底稿：`tech.origin`（typeVersion 1，cardinality one，scope company）
> 硬输入：`ip.portfolio`、`org.people`；软引用：`business.segment`

## 1. 一句话目标

回答三件事：**技术是自己做的、买来的、高校转化来的、还是逆向来的（证据是什么）**、**许可范围到哪（地域/期限/独占/再许可/改进归属）**、**有没有明显的 FTO 风险线索与商业秘密纠纷**。

> **边界（必须先读）**：本模块的 FTO 部分只做**线索与风险扫描**，输出"候选专利 + 权利要求要点 + 可能覆盖的产品特征 + 建议动作"。**不构成、也不冒充正式 FTO 法律意见**；不做侵权结论，不做有效性结论。

## 2. 输入、前置与输出

| 项 | 内容 | 缺失时 |
|---|---|---|
| `ip.portfolio` | 专利/商标/软著清单、法律状态、质押 | `onMissing: block`，否则无法判断转让/许可 |
| `org.people` | 创始人、核心技术人员、发明人 | `onMissing: block`，否则无法做"员工自带/职务发明"判断 |
| `business.segment`（软） | 产品与技术路线 | 缺失只警告；FTO 扫描只能到"技术大类"粒度 |

输出 `data`：`origins[]`、`licenses[]`、`ftoRisks[]`、`tradeSecretCases[]`。`{{params.jurisdictions}}` 控制 FTO 扫描辖区（默认 `CN,US,EP`），按逗号拆分，逐个辖区检索。

## 3. 口径定义

### 3.1 技术来源的七分类（`origins[].origin`）

| 取值 | 含义 | 最低证据要求（`basis`） |
|---|---|---|
| `自研` | 公司内部研发形成 | 研发投入/研发人员/专利原始申请人=公司/技术自述 + 至少一项旁证 |
| `引进` | 受让、购买、技术许可引进 | 专利转让登记、许可备案、技术引进合同公告 |
| `转化` | 高校/科研院所成果转化 | 高校技术转移公示、成果转化协议、作价入股公告 |
| `逆向` | 反向工程、仿制 | 判决/问询回复/公开表述（此类证据少，未证实不得写） |
| `合作研发` | 联合开发、共有专利 | 共有专利、联合实验室公告、合作协议 |
| `并购取得` | 通过收购主体取得 | 收购公告、标的专利清单 |
| `员工自带` | 核心人员从前雇主带来 | 履历 + 前雇主诉讼/竞业限制记录（须谨慎，避免人身推断） |

规则：
- `basis` 不是"证据类型标签"，而是**具体证据的一句话描述 + 证据 ID**；一个来源结论至少一条 `supports`。
- 公司自述"自主研发"只能证明"公司曾如此声明"，不能自动证明为真；必须有旁证（专利原始申请人、研发费用、研发人员、第三方鉴定）才可判 `found`。
- 多来源并存时（如"自研为主 + 部分许可"）分别建行，不要合并成一行。

### 3.2 许可（`licenses[]`）记录要素

五个属性必须写清：**许可方、地域、期限、独占性、再许可/改进归属**。落字段方式：许可方 → `licensor`；地域、期限、独占性 → `scope`；再许可、改进归属、提成 → `note`；生效状态 → `status`（有效/终止/未披露）。

- 许可类型必须写清：**独占 / 排他 / 普通**；独占许可对技术独立性影响最大。
- 地域与期限缺一不可；跨境许可还要看是否有出口管制/再出口限制。
- 许可 vs 转让：转让是权利转移（登记簿权利人变更），许可是使用授权（合同备案），**不得混写**。
- 许可费/提成（running royalty）如有披露，记入 `note`；未披露写 `not_disclosed_after_search`。

### 3.3 商业秘密案件（`tradeSecretCases[]`）

每条至少记：案号、法院、当事人（原告/被告）、案由、判决/调解结果、赔偿金额（如有）、是否涉及本公司核心技术或前员工。

- 来源：裁判文书、法院公告、上市公司公告、问询回复。
- 只写判决/公告明确表述的事实；**不推断"技术是偷来的"**。
- 涉及个人的，只记录与交易相关的任职/诉讼事实，不采集私生活信息。

### 3.4 开源协议（记入 `origins[].note` 或 `licenses[].note`）

- 记录产品中使用的开源组件、许可证类型（GPL/LGPL/Apache/MIT/BSD 等）、是否 copyleft、是否有合规声明/SBOM。
- 许可证类型只能从仓库 LICENSE 文件或官方声明确认；"GitHub 上写着开源"不等于可商用。
- copyleft 组件与闭源产品结合可能产生开放义务，只记核查项，不下法律结论。

### 3.5 FTO 风险扫描（只做线索）

扫描步骤：
1. 从 `business.segment` 取产品/技术特征（3–5 个关键特征）；
2. 在 `{{params.jurisdictions}}` 逐辖区检索**有效**专利（排除失效、期限届满）；
3. 用关键词 + IPC/CPC 分类号初筛，读权利要求**独立权利要求**；
4. 输出 `ftoRisks[]`：`patent`（专利号）、`holder`（权利人）、`jurisdiction`（辖区）、`note`（可能覆盖的特征 + 风险等级 + 建议动作）。

禁止：
- 不写"侵权/不侵权""规避设计可行/不可行"的结论；
- 不把"检索到相似专利"等同于"存在侵权风险"；
- 不省略"需专利律师做权利要求比对与侵权分析"的限定语。

## 4. 检索计划

来源优先级：**官方登记/裁判文书 > 高校与政府公示 > 论文与标准 > 公司披露 > 媒体**。

| # | 目标 | 首查来源 | 检索词（示例） | 判 found 的条件 |
|---|---|---|---|---|
| 1 | 专利转让 | CNIPA 登记簿（权利人变更）、转让登记 | `[A公司] 专利权转让`、`[A公司] 受让 专利` | 有登记变更 + 日期 + 原权利人 |
| 2 | 专利/技术许可 | CNIPA 许可合同备案、公告 | `[A公司] 专利实施许可`、`[A公司] 技术许可` | 有许可方 + 范围 + 备案号 |
| 3 | 高校成果转化 | 高校技术转移中心公示、作价入股公告 | `[高校名] 成果转化 [技术]`、`[A公司] 产学研` | 有公示 + 技术名 + 股权/许可安排 |
| 4 | 论文与技术出处 | CNKI/万方/Google Scholar、期刊 | `[技术关键词] [A公司]`、`[创始人名] 论文` | 有作者单位/致谢/基金号 |
| 5 | 商业秘密 | 裁判文书、法院公告 | `[A公司] 侵害商业秘密`、`[A公司] 不正当竞争` | 有案号 + 当事人 + 结果 |
| 6 | 开源合规 | 代码仓库 LICENSE、产品文档 | `[A公司] 开源`、`[产品名] open source` | 有许可证类型 + 组件名 |
| 7 | FTO 线索 | Espacenet/USPTO/CNIPA | 技术特征关键词 + IPC/CPC | 有有效专利 + 独立权利要求 |
| 8 | 技术引进合同 | 公告、招股书 | `[A公司] 技术引进`、`[A公司] 合作开发` | 有合同对方 + 范围 |

必查库：CNIPA（登记簿/许可备案/质押）、裁判文书与法院公告、高校技术转移公示、国家科技报告系统、CNKI/万方/Google Scholar、Espacenet/USPTO/WIPO、代码仓库；境外加 `patent assignment`、`license agreement`、`trade secret litigation`、`freedom to operate`。

## 5. 字段与口径映射

| 字段 | 定义 | 缺失处理 |
|---|---|---|
| `origins[].technology` | 技术/产品名 | 必填 |
| `origins[].origin` | 七分类之一 | 证据不足写 `not_reviewed`，不得猜 |
| `origins[].basis` | 证据描述 + 证据 ID | 必填；无证据不得判 `found` |
| `licenses[].licensor` | 许可方 | 未披露写 `pending_dd` |
| `licenses[].scope` | 地域/期限/独占性 | 未披露写 `not_disclosed_after_search` |
| `licenses[].status` | 有效/终止/未披露 | 必填 |
| `ftoRisks[].patent` | 专利号 | 必填 |
| `ftoRisks[].holder` | 权利人 | 必填 |
| `ftoRisks[].jurisdiction` | CN/US/EP/… | 必填 |
| `tradeSecretCases[]` | 每条：`caseNo`（案号）、`court`（法院）、`parties`（当事人）、`result`（结果）、`amount`（赔偿，可选）、`note`；无案号不得入表 | 无案件写空数组 + 已检索说明 |

## 6. 六态与边界

六态：`found` / `not_disclosed_after_search` / `lower_bound` / `pending_dd` / `conflict` / `not_applicable` / `not_reviewed` / `estimated`。

- `origins[].origin`、`origins[].basis`、`licenses[].scope`、`licenses[].status`、`ftoRisks[].holder` 必须能落六态并带 note。
- `maxEstimatedRatio` 0.2；`estimated` 只能用于"技术来源占比"这类分析型归纳，且必须带 `derivation`。
- **公司特定事实（是否自研、许可范围、诉讼结果）禁止用同行均值或行业惯例替代**；查不到写 `not_disclosed_after_search`。
- 只能 `pending_dd` 的：未备案的许可、内部技术引进合同、未公开的 FTO 分析报告、员工与原单位的保密/竞业协议。
- 不推断：不推断"技术是逆向来的"、不推断"窃取商业秘密"、不做侵权/有效性结论、不对个人做品行推断。

## 7. 常见误判（逐条对照）

1. **自述当证实**：把"公司坚持自主研发"直接写成 `origin=自研, status=found`。
2. **发明人当权利人**：专利发明人是员工，不代表技术来源是自研；受让专利的发明人常是原公司人员。
3. **许可当转让**：把许可备案写成"专利已转让"。
4. **开源=免费**：忽略 copyleft 义务与商用限制。
5. **FTO 扫描当法律意见**：输出"不侵权"结论，或省略"需律师比对"的限定。
6. **论文致谢当合作研发证据**：致谢只说明有交流，不足以证明成果归属。
7. **框架协议当已受让**：技术合作框架协议、意向书不等于权利已转移。
8. **诉讼当定罪**：有商业秘密诉讼不等于公司侵权，需看判决结果与当事人。

## 8. 验收要点

- `minEvidence: 3`、`minCoverage: 0.7`；`data.origins` ≥1 行。
- 每条 `origins` 有 `basis` 且能对上至少一条 `evidence`；`origin` 取值合法。
- `licenses[]` 每条有 `scope`（地域/期限/独占性）或明确六态。
- `ftoRisks[]` 每条含专利号、权利人、辖区，并在 `note` 含"线索/需律师比对"限定语。
- `tradeSecretCases[]` 每条有案号或公告来源；无则空数组 + 已检索说明。
- 开源相关结论必须能指到 LICENSE 或官方声明。

### 8.1 样例（占位符）

```
origins[0] = {technology:"技术甲", origin:"转化", basis:"高校技术转移公示（证据 ev_01）+ 作价入股公告（ev_02）", note:"found｜许可/入股范围见 licenses"}
licenses[0] = {licensor:"高校/许可方（占位）", scope:"地域=CN；期限=20XX-20XX；类型=独占；不再许可", status:"有效", note:"found｜合同备案号（占位）"}
ftoRisks[0] = {patent:"专利号（占位）", holder:"权利人（占位）", jurisdiction:"US", note:"线索：独立权利要求可能覆盖特征甲；需专利律师做权利要求比对与侵权分析"}
tradeSecretCases[0] = {caseNo:"案号（占位）", court:"法院（占位）", parties:"原告/被告（占位）", result:"判决结果（占位）", note:"公开裁判文书"}
```

## 9. 与其他模块的关系

- **上游**：`ip.portfolio`（权利清单与状态）、`org.people`（发明人与核心人员）。
- **下游**：`assessment-fit`（技术自主性）、`red-flags`（T4 发明人与核心人员重叠、T5 技术宣称与专利覆盖）、`policy-exposure`（技术出口管制）。
- **交叉**：`business.segment`（技术路线）、`legal-risk`（诉讼）、`debt.guarantee`（技术质押融资）。
- 与 `ip-portfolio` 的边界：本模块判断"**技术从哪来、许可到哪、有无 FTO 线索**"；权利清单与法律状态归 `ip-portfolio`。

## 10. 版本与状态

- 模块状态：`draft`，未经金融专家评审；FTO 部分为线索扫描，**不构成法律意见**。
- 许可与诉讼时效性强：每次重跑必须重查状态与最新裁判，不得沿用旧结论。
