# 未 stable 方向的最低调查清单 · 技术来源、许可与 FTO 线索

> 用途：预算不足或只能取得公开登记时的最小集合。不降低证据与六态要求；FTO 部分始终只做线索。

## 1. 最低必查

1. **一项核心技术的来源**：给出七分类之一与至少一条可打开证据（专利原始申请人/公示/合同公告/判决）。
2. **一次许可或转让核验**：CNIPA 登记簿（权利人变更）或许可合同备案查一次，记录有/无。
3. **一次高校/院所公示检索**（如公司有产学研背景）：按技术名 + 高校名检索公示。
4. **一次商业秘密检索**：裁判文书按公司名 + "商业秘密/不正当竞争"检索。
5. **一次 FTO 线索扫描**：在 `jurisdictions` 中至少一个辖区，用产品关键特征 + IPC/CPC 初筛有效专利，给出候选与限定语。

## 2. 最低可交付字段

| 字段 | 最低要求 | 不满足时 |
|---|---|---|
| `data.origins[]` | ≥1 行，含 technology/origin/basis | 无来源证据 → `not_reviewed`，不得判 `自研` |
| `data.licenses[]` | 可为空，需说明已检索备案 | 空且无说明 → 门不过 |
| `data.ftoRisks[]` | 可为空，需说明已扫描辖区 | 空且无说明 → 门不过 |
| `data.tradeSecretCases[]` | 可为空，需说明已检索渠道 | 同上 |
| `claims` | ≥3 条，≥1 条 material | 证据不足 → 门不过 |

## 3. 必须标注的缺口

- 未备案的技术许可与内部技术引进合同。
- 员工与原单位的保密/竞业协议（涉及个人，不主动采集）。
- 未公开的 FTO 分析报告与专利律师意见。
- 尚未公开的专利申请对应的许可/转让。
- 境外辖区的完整扫描（默认 CN/US/EP，未覆盖 JP/KR 等）。
- 开源组件的完整 SBOM 与许可证清单。

## 4. 禁止的凑数做法

- 用公司自述"自主研发"直接判 `found`。
- 用同行技术来源替代。
- 把许可写成转让、把意向书写成已签约。
- FTO 输出侵权结论或"已规避"表述。
- 用论文致谢推断成果归属。
- 把"没有检索到诉讼"写成"不存在纠纷"（应写 `not_disclosed_after_search` 并附检索记录）。

## 5. 交付话术（供交付模块引用）

> 本模块为 draft 方法论，未经金融专家评审。技术来源以公开登记与公示为限，未取得的合同与内部文件已在底稿标注；FTO 部分仅为线索扫描，不构成法律意见，需由专利律师另行出具正式分析。
