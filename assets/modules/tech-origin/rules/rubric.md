# 审核 rubric · 技术来源、许可与 FTO 线索（tech-origin）

> 模块状态：**draft**，未经过金融专家评审。FTO 部分为线索扫描，**不构成法律意见**。
> 评分对象：单个 `tech.origin` 底稿。五维各 1–5 分，**任一维 ≤2 即整体不通过**。

## 1. 五维评分表

| 维度 | 1 分 | 2 分 | 3 分（及格线） | 4 分 | 5 分 |
|---|---|---|---|---|---|
| **事实准确性** | 技术来源与证据相反，或凭空下"自研"结论 | 依赖公司自述，无旁证；许可/诉讼事实有误 | 每条 `origin` 有 `basis` 且与证据一致；许可范围与诉讼结果与原文一致 | 来源、许可、诉讼均可回溯到登记/公示/判决原文 | 技术—产品—专利—合同四者对应，来源判断给出旁证链并保留反证 |
| **引用准确性** | 引文不存在 | 无 locator 或引文为改写 | 引文为原文片段，locator 到段落/页 | 每条 material claim 有 supports | 关键结论有双源（如登记 + 公示），来源独立性已核 |
| **完整性** | 只有一句"自主研发" | 缺许可或诉讼或开源 | 来源、许可、FTO 线索、商业秘密四块均有覆盖 | 含转让、开源、多辖区 FTO | 逐技术逐产品覆盖，许可五要素齐全，FTO 逐辖区逐权利要求要点 |
| **来源质量** | 仅媒体/公司宣传 | 以公司自述为主 | 官方登记/裁判文书/公示为主 | 官方 + 论文/标准交叉 | 官方登记簿 + 判决 + 高校公示 + 官方专利库四源交叉 |
| **对账** | 来源结论与专利清单矛盾且未解释 | 发明人/权利人混用 | 来源与 `ip.portfolio` 的权利人、申请人一致 | 与许可备案、质押、诉讼可对齐 | 与 `ip.portfolio`、`org.people`、`legal.risk` 三处闭合，差异有说明 |

## 2. 3 分与 5 分的判据

**3 分**
- `origins[]` 覆盖主要技术，每条有 `origin`（七分类之一）与 `basis`（能对上证据）。
- `licenses[]` 至少覆盖已披露的许可，含许可方与范围（或六态）。
- `ftoRisks[]` 至少给出候选专利与权利人，note 含"线索 + 需律师比对"限定。
- `tradeSecretCases[]` 如有，含案号与结果；无则说明已检索渠道。

**5 分**
- 每项核心技术的来源都有"主证据 + 旁证"（如专利原始申请人 + 研发费用 + 公示），公司自述只作辅助。
- 许可五要素（许可方、地域、期限、独占性、再许可/改进归属）齐全，并与备案号、合同公告对应。
- FTO 按 `jurisdictions` 逐辖区给出候选专利、独立权利要求要点、可能覆盖的产品特征，明确建议交专利律师，全程无侵权结论。
- 商业秘密案件逐条落案号、当事人、结果、赔偿，并说明与本公司技术/人员的关系（仅限公开表述）。

## 3. 门与一致性判定（本模块）

| 门/规则 | 含义 | 不过的处理 |
|---|---|---|
| `minEvidence: 3` | 证据 ≥3 条 | 判 2 分（引用准确性） |
| `minCoverage: 0.7` | 必答问题覆盖 ≥70% | 判 2 分（完整性） |
| `minItems.data.origins: 1` | 来源至少 1 行 | 无则插 `not_applicable` 占位并说明 |
| `sixStateFields` | 来源、依据、许可范围、许可状态、FTO 权利人必须落六态 | 空白即判 2 分 |
| `maxEstimatedRatio: 0.2` | 估算 ≤20% | 超限判 2 分 |
| `origin-enum` | 来源取值合法 | `block` |
| `fto-no-conclusion` | FTO 说明不得含侵权/规避结论词 | `block`，删除结论后重提 |
| `fto-clue-tagged` | 每条 FTO 说明必须含"线索" | `block` |
| `license-scope-required` | 有许可方必须有范围 | `block` |
| `case-number-required` | 有当事人必须有案号 | `attention` |

一致性 `kind` 语义（本模块用到）：`enum` 取值域；`banned_terms` 禁止词；`tag_required_all` 每个元素都必须含标签；`required_with` 条件必填。六态在标量字段上写在行 `note` 开头（`found｜…`）。

## 4. 一票否决项

1. 编造技术来源、许可方、许可范围、案号或 URL。
2. 仅凭公司自述把 `origin` 判为 `自研` 且 `status=found`。
3. FTO 输出"侵权/不侵权/规避可行"等法律结论，或省略"需律师比对"限定。
4. 把许可写成转让、把框架协议写成已受让。
5. 用同行技术路线替代本公司技术来源。
6. 声称本模块 `stable` 或"专家已审"。
