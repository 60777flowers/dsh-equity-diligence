# 审核 rubric · 关联方与关联交易（related-parties）

> 模块状态：**draft**。本 rubric 供人工/评审代理使用，不代替金融专家评审。
> 评分对象：单个 `related.parties` 底稿（一个公司、一个 asOf）。五维各 1–5 分，**任一维 ≤2 即整体不通过**。

## 1. 五维评分表

| 维度 | 1 分 | 2 分 | 3 分（及格线） | 4 分 | 5 分 |
|---|---|---|---|---|---|
| **事实准确性** | 关联方/交易与来源明显不符，或存在虚构主体 | 多处关系性质或金额错位，口径未标 | 主要关联方与交易金额与来源一致；口径（会计/上市规则）已标注；个别次要字段存疑但有 note | 全部事实可回溯到公告/附注原文，口径、期间、含税性一致 | 事实与原文逐项对得上；两套口径差异被显式保留为 `conflict`/并列，且解释了差异来源 |
| **引用准确性** | 引文不存在或指向无关页面 | 引文为改写，locator 缺失 | 引文为原文片段，locator 到章节/页码，来源可打开 | 每条 material claim 有 ≥1 条 supports，且引文可精确命中 | 关键金额有双源交叉，来源独立性（`originGroupId`）已核，转载未当独立源 |
| **完整性** | 只有零散几条，缺交易金额与审批 | 缺一个口径，或漏掉主要交易类型 | 关联方清单、交易要素（对手方/方向/金额/期间/定价/审批）、重叠核查均有覆盖；缺失项写了六态 | 覆盖会计+上市规则双口径，含 12 个月时点规则与子公司 | 双口径 + 母公司/合并 + 资金占用/担保 + 交叉重叠全部覆盖，缺口逐条进 `openQuestions` |
| **来源质量** | 仅媒体/自媒体 | 以工商快照或公司自述为主 | 以公告/年报附注/招股书为主，工商为辅 | 以监管/交易所原始披露为主，多源独立 | 一手披露 + 独立第三方（工商、判决、问询回复）交叉，且注明各源权威性 |
| **对账** | 金额与下游财务底稿明显矛盾且未解释 | 期间或口径不一致，未标注 | 金额、期间、方向内部自洽；与 `financials.public` 的差异有 note | 与股权链、客户供应商名单可对齐，重叠项可定位 | 全量对账：交易对手↔关联方↔股权链↔客户/供应商四处闭合，差异有 `conflictGroup` 与裁决理由 |

## 2. 3 分与 5 分的判据（必须能指着底稿说清）

**3 分（及格）**
- `parties[]` 每条都有 `relation`（关系性质 + 口径）与 `note`；`transactions[]` 至少覆盖金额、方向、期间、定价、审批中的四项，缺项为六态而非空白。
- 主要结论（关联方数量级、关联交易金额量级、是否存在资金占用）与来源一致，允许次要字段 `not_disclosed_after_search`。
- `overlapFlags[]` 只含核查动作。

**5 分（优秀）**
- 会计口径与上市规则口径**分别成表或分别标注**，两者覆盖范围不同的主体写 `conflict` 并说明"为何两套口径不同"，不是简单取并集。
- 每笔重大关联交易能追到"公告/附注原文 + 页码 + 期间 + 含税口径 + 审批会议届次"；定价有可比依据（第三方报价/评估/招投标）。
- 12 个月时点规则、母公司报表附注、子公司关联交易均已检查，并在 `sourceCoverage.limitations` 说明未覆盖部分。
- 与 `ownership.chain`、`valuechain.parties` 的交叉结果可一一对应到具体主体，不出现"疑似关联方"这类无证据表述。

## 3. 门与一致性判定（本模块）

`rules/gates.json` 的门为确定性判定，评审时只核对是否被正确执行：

| 门/规则 | 含义 | 不过的处理 |
|---|---|---|
| `minEvidence: 4` | 可打开证据 ≥4 条 | 判 2 分（引用准确性），退回补证 |
| `minCoverage: 0.7` | 必答问题覆盖 ≥70% | 判 2 分（完整性） |
| `minItems.data.parties: 1` | 关联方至少 1 行 | 无则插 `not_applicable` 占位并说明 |
| `sixStateFields` | 四个关键字段必须能落六态并带 note | 空白即判 2 分 |
| `maxEstimatedRatio: 0.1` | 估算字段占比 ≤10% | 超限判 2 分（事实准确性），要求改 `pending_dd` |
| `tx-direction-enum` | 方向取值合法 | `block`，直接退回 |
| `tx-counterparty-in-parties` | 交易对手能对上关联方清单 | `attention`，进 `openQuestions` |
| `tx-period-with-amount` | 有金额必须有期间 | `block` |
| `overlap-no-conclusion` | 重叠说明不得含定性词 | `block`，删除定性表述后重提 |

一致性 `kind` 语义（仅列本模块用到的）：`enum` 取值域；`subset_of` 左集合须为右集合子集；`required_with` 当 `when` 有值时 `path` 必填；`banned_terms` 指定字段不得含给定词。`onFail=block` 表示门不过需返工，`attention` 表示记录并提示。

## 4. 一票否决项（直接不通过，不进入打分）

1. 编造关联方主体、交易金额、公告编号或 URL。
2. 把会计口径与上市规则口径混成一套并据此下"未披露"结论。
3. 用同行均值/行业惯例替代公司特定关联交易数据。
4. 在 `note`/`flags` 中把重叠或交易直接定性为"利益输送""违规""虚增"。
5. 声称本模块 `stable` 或"专家已审"。
