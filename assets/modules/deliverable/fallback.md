# 兜底清单 · 交付构建（未 stable 方向的最低交付）

> 适用：只有 skill-only/quick 预设、部分模块缺失、证据快照不全、时间只够出一版草稿。
> 兜底不降低“报告不得创造底稿之外新事实”的要求。模块状态 `draft`。

## 1. 最低必交付（六件）

1. `01_管理层摘要.md`：5–10 条五段式，每条挂 `claimId`。
2. `02_综合尽调工作簿.xlsx`：至少含 目录、摘要、主体股权、风险、待核、资料请求、来源索引、底稿索引、体检 九个页签。
3. `04_工作底稿/<moduleId>/workpaper.md`：每个已运行模块一页。
4. `manifest.json`：文件清单 + `sha256`。
5. `QA与签发记录.md`：阻断/非阻断项 + 复核人。
6. `dd.request_list`：待核与资料请求合并去重。

7+N 专项在 `investment.map` 缺失时可不出，但必须在 QA 记非阻断项并说明原因。

## 2. 摘要不足 5 条时

- 不得为凑数拆分同一事实；宁可在体检页写“调查覆盖不足，摘要仅 N 条”。
- 若确实只有 3–4 条可交付事实，视为阻断：补查上游或降级为“阶段性简报”，不得伪装成完整交付。
- `material` 红旗即使只有 1 条，也必须进首页。

## 3. 结构可裁剪的部分

| 项 | 可裁剪 | 条件 |
|---|---|---|
| 03 专项 7+N | 是 | `investment.map` 缺失；说明页写“未生成原因” |
| 05 证据快照 | 部分 | 仅保留摘要引用的证据；其余标 `pending_dd` |
| PDF | 是 | 先出 Markdown，PDF 另行验收 |
| 家族分表 | 是 | 主导群体不足 3 个时属正常，不得虚增 |

## 4. 必须写进底稿的三句话

- 哪些页签/产物被裁剪、为什么、对读者有什么影响。
- 哪些数字只有单一来源、哪些字段是 `pending_dd`。
- 阻断项是否已清零；未清零时不得签发。

## 5. 明确不做

- 不为叙事顺畅补数字、补主体、补日期。
- 不手工标绿、不重命名列、不合并七张固定表。
- 不把 `stale`/`rejected` 底稿当已验证引用。
- 不代替人工填 `approvedBy`/`signedAt`。
- 不在兜底模式下宣称“完整交付”或“专家已审”。
