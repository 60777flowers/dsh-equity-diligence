# 兜底清单 · 主体识别（未 stable 方向的最低调查）

> 适用：境外登记不可达、工商数据源限流、目标名严重不确定、预算不足以完成完整双源时。
> 兜底不降低“不编造”的要求：宁可写 `pending_dd`，不写猜测。模块状态 `draft`。

## 1. 最低必做（四项，缺一不可）

1. **一个可回查的法定名称**：至少一条 A 或 B 级来源给出全称，记录 URL、抓取时间、原文片段。
2. **一个可回查的标识**：境内 18 位统一社会信用代码（校验位说明是否通过）或境外注册号 + 辖区；没有就写明“无公开注册号”及已查机关。
3. **一个明确的状态口径**：状态 + 快照日期；不得把“未查到注销记录”写成“存续”。
4. **一条实控人线索或“无线索”结论**：公告口径表述原文；没有公告就写 `not_disclosed_after_search` 并列出查过的公告库与关键词。

## 2. 分场景下限

| 场景 | 最低动作 | 允许的六态 |
|---|---|---|
| 境内正常主体 | 登记机关 A 级 + 工商快照 B 级交叉 | `found` |
| 境内快照过期 | 以登记机关为准，记录两源差异 | `conflict` 或 `found` + note |
| 境外主体（港/新/美） | 当地登记机关页面 + 英文检索各一条；无注册号写“需注册证书” | `pending_dd` |
| 离岸主体（BVI/开曼） | 注册代理摘要或上市公告中的注册信息；注明不可回查 | `pending_dd` / `not_disclosed_after_search` |
| 目标名不确定 | 列 2–5 个候选（`maxCandidates` 内），逐个给代码与差异 | `conflict` + `resolution.candidates` |
| 预算耗尽 | 保留已得字段，其余 `not_reviewed`，在 `openQuestions` 写恢复点 | `not_reviewed` |

## 3. 兜底时必须写进底稿的三句话

- 哪些库/站/公告栏查过、用的什么词、哪一天查的（对应 `search.ledger`）。
- 哪一项最可能不完整、缺了会影响下游哪个判断。
- 下一步由谁、用什么材料补（营业执照、注册证书、章程、企业版数据库）。

## 4. 明确不做

- 不用同行均值、行业惯例或“通常如此”替代主体事实。
- 不把媒体简称直接当法定全称，不把上市代码当信用代码。
- 不因兜底而跳过 `roster` 覆盖：未解析的 target 必须留在 `openQuestions`，不得静默丢弃。
- 不在兜底模式下标注“已验证”“专家已审”。
