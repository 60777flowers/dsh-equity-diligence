# 审核 rubric · 主体识别与工商底册

> 五维各 1–5 分；**任一维 ≤2 分即不通过**。评分依据是底稿 JSON 与证据原文，不是叙述是否好看。
> 模块状态 `draft`：本 rubric 由模块作者编写，尚未经金融专家评审。

## 1. 事实准确性（identity facts）

| 分 | 判据 |
|---|---|
| 5 | 法定全称、代码、注册地、成立日、状态五项与登记机关逐字一致，代码校验通过；别名逐项标明类型；无一处与证据矛盾 |
| 4 | 上述五项齐全，最多一项为 `not_disclosed_after_search` 且有检索记录 |
| 3 | 五项齐全但有一项仅有单一 C 级来源，或成立日/注册资本口径（认缴/实缴、币种）未写清 |
| 2 | 出现同名不同主体混用、上市代码当信用代码、法定代表人写成实控人之一 |
| 1 | 主体识别错误，或大量字段无来源 |

## 2. 引用准确性（evidence）

| 分 | 判据 |
|---|---|
| 5 | 每条 material claim 至少一条 `supports`，`quote` 为原文片段、`locator` 可回查，双源独立性经 `originGroupId` 去重后成立 |
| 4 | 全部 material claim 有引文，个别 locator 只到页面级 |
| 3 | 主要结论有引文，但存在 1–2 条引文为转述而非原文，或双源实为同一转载 |
| 2 | 关键结论只有媒体线索，或引文无法在快照中命中 |
| 1 | 无引文、编造 URL/编号，或把公司自述当第三方验证 |

## 3. 完整性（coverage）

| 分 | 判据 |
|---|---|
| 5 | `roster` 全部 target 有 `resolution`；`aliases` 覆盖简称+曾用名；`identifiers`、`branches` 有检索记录；`openQuestions` 全是一句话能执行的下一步 |
| 4 | target 全覆盖，别名或分支有一项未查 |
| 3 | target 全覆盖，但 2–3 个字段以“未查到”收尾且未写已尝试路径 |
| 2 | 有 target 未解析，或整块字段缺失 |
| 1 | 只解析了部分目标且未说明 |

## 4. 来源质量（source quality）

| 分 | 判据 |
|---|---|
| 5 | 以 A 级登记/公告为主，B 级交叉；无 D 级来源进入结论；境外主体有英文检索记录 |
| 4 | A+B 为主，个别字段只有 B 级 |
| 3 | 主要字段来自 B 级工商快照，A 级仅作点缀 |
| 2 | 多数结论依赖 C/D 级来源 |
| 1 | 依赖传闻、百科或无法回查的页面 |

## 5. 对账（consistency）

| 分 | 判据 |
|---|---|
| 5 | `codeNameUnique`、`resolutionCoversTargets` 全通过；`flags` 与 `conflictGroup` 无未处理冲突；无 `estimated` |
| 4 | 对账通过，个别冲突已记录但 `decidedBy` 缺失 |
| 3 | 有一处金额/日期/币种口径不一致但已标注 |
| 2 | 存在未处理的同名/双代码冲突，或 `resolution` 缺项 |
| 1 | 底稿内部自相矛盾且无说明 |

## 判定与记录

- 五维分数、扣分理由、对应 `claimId`/`evidenceId` 写入底稿 `checks[]` 与 `openQuestions`。
- 任一维 ≤2：退回补查，不得进入 `ownership-chain`。
- 3 分是“可交付但需在摘要标注局限”，5 分是“可直接引用、无需二次核验”。
