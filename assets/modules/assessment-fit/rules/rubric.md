# assessment-fit · 审核 rubric（五维 1–5 分）

> 适用：`assessment.fit` 底稿复核。任一维 ≤2 分不通过；本模块为 `draft`。
> 特别说明：本模块是**判断类**产物，评分重点不在"结论是否正确"，而在"结论是否被证据支撑、是否越界"。

## 1. 事实准确性

| 分 | 判据 |
|---|---|
| 5 | a/b/c/d 四项判断与产品、验证阶段、技术路线的公开证据逐项对应；未把送样当量产；未把行业周期写成公司进度 |
| 3 | 主要判断有依据，个别项只有间接证据但已标 `pending_dd` |
| 1–2 | 用"技术相关"一句话代替逐项判断；把客户名单当已供货；把行业认证周期写成公司事实 |

## 2. 引用准确性

| 分 | 判据 |
|---|---|
| 5 | `conclusion.basis[]` 每一项都能追到 claimId 或证据；`approach` 的理由有出处 |
| 3 | 主要结论有依据，个别理由为分析推断但标注了 `derivation` |
| 1–2 | 结论无 basis；basis 指向不存在的 claimId；理由为"行业普遍认为" |

## 3. 完整性

| 分 | 判据 |
|---|---|
| 5 | 三个六态对象都填且有 note；a/b/c/d 逐项结论；合作方式与下一步具体；局限写清 |
| 3 | 三个对象都填，但 a/b/c/d 中有一项未单独结论；`approach` 只有 1 种方式 |
| 1–2 | 只填 `technologyFit`；`equityView` 留空；无局限性说明 |

## 4. 来源质量

| 分 | 判据 |
|---|---|
| 5 | 关键判断取公告/供应商目录/招投标/专利等一手来源；委托方背景只用项目内文件 |
| 3 | 主要依据 A/B 级来源，个别用权威媒体并标注 |
| 1–2 | 依据媒体转述或行业报告；联网搜索委托方背景；编造合作意向 |

## 5. 对账

| 分 | 判据 |
|---|---|
| 5 | 与 `business.segment` 的产品结构、`ownership.chain` 的股权结构、`investment.map` 的已有关系一致；技术/商业结论与投资结论未互相推导 |
| 3 | 有 1 处口径差异（如产品分类）且已说明 |
| 1–2 | 产品描述与 `business.segment` 矛盾；已有投资关系被忽略；技术结论直接推出投资结论 |

## 记录要求

- 每条扣分写：维度、字段路径（如 `data.technologyFit`）、理由、需补证据；
- 结论"高/中/低"本身不参与评分，越界（给投资建议、编造委托方背景）才扣分；
- 复核人只能提修订，不得自行改为 `verified`，也不得把本模块结论当作投资决策依据。
