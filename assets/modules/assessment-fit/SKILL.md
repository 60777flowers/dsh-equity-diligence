# assessment-fit · 合作契合度（委托方视角）

> 模块状态：**draft**。方法论未经金融专家评审，不得声称 `stable` 或"专家已审"。
> 输出底稿：`assessment.fit`（scope=company，cardinality=one，partitionKey=`_default`）。
> 一句话目标：从委托方视角回答"这家公司跟我们有没有技术/商业合作空间"，并把股权投资判断**单独**写成 IC 输入，两者不混。

## 1. 回答什么问题

1. 这家公司的产品/技术是否落在委托方需要的环节（a/b/c/d 四项对照）？
2. 有没有进入委托方或主流晶圆厂的验证/量产记录？处在哪个阶段（送样、单项验证、小批量、量产导入）？
3. 是否国产替代直接受益？卡的是哪个环节？
4. 商务上可行吗：产能、价格、交付、认证周期、客户关系、地域？
5. 适合哪种合作方式（送样验证、联合开发、技术授权、代工、供货、合资、股权投资）？
6. 从股权投资角度，它是什么状态（估值、轮次、股权结构、治理、退出）？——**只作 IC 输入，不给建议**。

## 2. 输入、前置与降级

| 关系 | 类型 | 说明 |
|---|---|---|
| 硬输入 | `ownership.chain` | 股权结构、控制权、特殊权利，决定能否投资与治理安排 |
| 硬输入 | `business.segment` | 产品、技术路线、收入结构，决定技术关联 |
| 硬输入 | `investment.map` | 委托方体系是否已与其存在投资/合作关系（避免重复与利益冲突） |
| 软引用 | `ip.portfolio` | 专利与布局，佐证技术能力 |
| 软引用 | `financials.public` | 收入、毛利、研发投入，佐证商业可行性 |
| 软引用 | `tech.origin` | 技术来源，判断自主性 |

- 降级：无 `investment.map` 时不得启动（block）：无法判断是否已有投资关系。
- 分区：单一 artifact，`{{unit.partition}}` 恒为 `_default`。
- 委托方档案由 `{{params.clientProfile}}` 指定，默认 `example`；**不得联网搜索或编造委托方背景**，只用项目内 `00_基准/委托方背景.md` 或内置背景。

## 3. 评估框架

### 3.1 技术关联四项（a/b/c/d）

| 项 | 问题 | 判定要点 |
|---|---|---|
| a | 产品/技术是否落在委托方所需环节（设备、材料、零部件、EDA/IP、量检测、封测等） | 有明确的产品对应关系，不是"泛半导体" |
| b | 是否已有进入委托方或主流晶圆厂的验证/量产记录 | 有客户验证公告、供应商目录、量产供货证据；"送样"不等于"导入" |
| c | 是否国产替代直接受益（进口受限环节优先） | 该环节境外依赖度高、国产化率低、有替代政策或客户导入意愿 |
| d | 技术路线是否与委托方工艺兼容 | 工艺节点、材料体系、设备接口、良率要求 |

四项逐项给"是/否/证据不足"，不得只给一个总分。

### 3.2 合作方式与适用条件

| 方式 | 适用条件 | 需要核什么 |
|---|---|---|
| 送样验证 | 产品已定型、有对应产线需求 | 验证窗口、技术对接人、试样数量 |
| 联合开发（JDA） | 双方技术互补、需定制 | IP 归属、排他性、开发费用分担 |
| 技术授权 | 对方有核心 IP、委托方需快速补齐 | 授权范围、地域、期限、费用结构 |
| 代工/封测 | 产能与工艺匹配 | 产能锁定、良率、交付周期 |
| 供货（客户关系） | 已通过验证、有采购需求 | 认证进度、价格、账期、二供策略 |
| 合资 | 需要深度绑定、涉及产能或地域 | 出资比例、控制权、退出机制 |
| 股权投资 | 战略协同 + 财务回报双重目标 | 估值、轮次、治理、回购、退出 |

### 3.3 技术/商业适配 vs 股权投资（硬性分离）

- `technologyFit`：技术是否对得上（a/b/c/d）；
- `commercialFit`：商务是否走得通（产能、价格、交付、认证周期、客户关系）；
- `equityView`：股权投资视角（估值、轮次、股权结构、治理、退出、财务质量）。

三者分别给结论与证据。**不得因为技术对得上就推导"值得投"**；也不得因为估值贵就否定技术合作。`equityView` 只作 IC 输入，明确写"不构成投资建议"。

### 3.4 认证周期这一约束

委托方背景中"新设备/新材料进入产线通常需 12–24 个月以上认证"是**委托方口径的行业约束**，不是被评估公司的事实。写进 `commercialFit` 时必须标明"按委托方公开口径的行业认证周期"，不得写成"该公司认证需 18 个月"。

### 3.5 判断分级标准（避免"感觉很好"）

| 等级 | technologyFit | commercialFit |
|---|---|---|
| 高 | a、b、d 三项有证据，b 项已到小批量或量产导入 | 产能、价格、交付、认证四项中三项明确且无硬约束 |
| 中 | a、d 匹配，b 项仅送样或单项验证 | 有两项明确，认证周期偏长或价格待定 |
| 低 | a 项勉强对应，b 项无量产记录，d 项不匹配 | 产能不足、交付不达标或客户关系薄弱 |
| 不适合 | 产品不在委托方所需环节 | 商务上无法形成可持续供货 |

分级必须在 note 写"依据哪几项"，不得只给等级。

## 4. 字段与口径

| 字段 | 结构 | 定义 | 什么算 `found` |
|---|---|---|---|
| `data.technologyFit` | 六态对象 | 技术适配结论 | a/b/c/d 至少三项有证据支撑 |
| `data.commercialFit` | 六态对象 | 商业适配结论 | 有产能/价格/交付/认证中至少两项证据 |
| `data.equityView` | 六态对象 | 股权投资视角 | 有估值、轮次、股权结构中的两项以上 |
| `data.approach[]` | `mode`/`rationale`/`nextStep` | 建议的合作方式 | 每种方式都有理由与下一步 |
| `data.conclusion` | `technologyCommercial`/`equityInvestment`/`basis[]`/`limitations[]` | 结论与边界 | 结论明确且 basis 引用 claimId/evidenceId |

- 三个六态对象必须带 `status`、`value`、`note`；`value` 用 `高`/`中`/`低`/`不适合` 四档之一（equityView 用 `具备条件`/`需观察`/`不具备条件`/`unknown`）。
- `approach[].mode` 用 3.2 表中的固定词；`nextStep` 写"谁在什么时间做什么"，不写"加强沟通"这类空话。
- `conclusion.technologyCommercial` 与 `conclusion.equityInvestment` 分别写一句话结论，不得合并成"综合评估良好"。

### 4.1 结论必须可追溯

`conclusion.basis[]` 的每一项必须是 claimId 或"字段路径 + 证据ID"，例如 `cl_0012（b 项：已进入某晶圆厂量产供货）`。没有依据的判断只能放 `limitations[]`，不得放进 `basis`。

### 4.2 六态适用

- `found`：有证据支撑的判断；
- `lower_bound`：只知道"至少达到某阶段"（如仅知已送样、无法确认是否通过），按已知下限给结论并在 note 写明；
- `estimated`：只能用于"适配度打分"这类分析型判断，且必须带 `derivation`（方法、输入、可比对象、假设）；
- `pending_dd`：需要客户验证进度、产能确认、报价单；
- `not_disclosed_after_search`：查过公开渠道仍无关键信息；
- `conflict`：不同来源对同一能力判断矛盾；
- `not_applicable`：业务与委托方完全无关；
- `not_reviewed`：本轮未评估。

### 4.3 字段填充示例（占位符，不是真实数据）

```jsonc
{
  "technologyFit": {"status": "found", "value": "中", "note": "a、d 项匹配；b 项仅送样，无量产记录"},
  "commercialFit": {"status": "found", "value": "中", "note": "产能可覆盖，认证周期按委托方口径 12–24 个月"},
  "equityView": {"status": "pending_dd", "value": "需观察", "note": "估值与轮次信息不足，需补充"},
  "approach": [
    {"mode": "送样验证", "rationale": "产品对应产线需求且已有试样", "nextStep": "由委托方工艺团队安排验证窗口"}
  ],
  "conclusion": {
    "technologyCommercial": "适合技术合作（中高），建议先走送样验证",
    "equityInvestment": "暂不具备判断条件，仅作 IC 输入",
    "basis": ["cl_0012（b 项验证进度）", "cl_0018（产能与交付）"],
    "limitations": ["未取得客户验证报告", "估值信息未披露"]
  }
}
```

## 5. 六态与边界

- 三个六态对象**不得为空**，每个都要 `status` + `note`；
- `estimated` 只用于适配度判断，且必须带 `derivation`；
- 公司特定事实（收入、客户、产能、估值）禁止用同行均值替代；
- 边界：不给投资建议、不承诺合作、不评价委托方战略、不替代尽调与法务；`equityView` 只作 IC 输入。

## 6. 常见误判

1. 把"技术相关"直接推导成"值得投资"。
2. 把"送样/试样"当成"通过验证"或"量产导入"。
3. 把客户名单里出现某晶圆厂当成"已供货"。
4. 把技术授权协议签署当成合作落地。
5. 用同行估值或行业平均毛利替代本公司数据。
6. 把委托方背景里的行业认证周期写成被评估公司的认证进度。
7. 用"协同效应大"这类空话替代具体合作方式与下一步。
8. 把 `equityView` 写成投资建议（"建议投资/不建议投资"）。
9. 三个六态对象只填一个，另外两个留空。
10. 结论没有 basis，或 basis 指向不存在的 claimId。

## 7. 验收要点

- 证据：≥3 条新增证据；技术关联四项逐项有结论；
- 覆盖：`technologyFit`、`commercialFit`、`equityView` 三个六态对象都填；
- 分离：技术/商业适配与股权投资结论分开写，未互相推导；
- 必答：①a/b/c/d 四项逐项结论；②当前验证/供货阶段；③建议的合作方式与下一步；④股权投资视角的关键缺口；⑤结论的局限；
- 一致性：与 `business.segment` 的产品结构、`ownership.chain` 的股权结构、`investment.map` 的已有关系不矛盾。

## 8. 与其他模块的关系

- 上游（硬）：`ownership.chain`、`business.segment`、`investment.map`；软引用 `ip.portfolio`、`financials.public`、`tech.origin`；
- 下游：`deliverable`（摘要中的合作建议）、`red-flags`（若评估发现新风险）；
- 不重复：技术能力事实归 `ip-portfolio`/`tech-origin`；财务归 `financials-public`；估值归 `financing-history`；本模块只做"适配判断"与"合作路径"。

## 9. 交付前自检

- [ ] a/b/c/d 四项逐项有结论，不是一句"技术相关"
- [ ] 三个六态对象都有 status 与 note
- [ ] 技术/商业适配与股权投资结论分开
- [ ] 每条结论都有 basis 指向 claimId 或证据
- [ ] `approach` 的 nextStep 具体到"谁做什么"
- [ ] 没有投资建议式表述
- [ ] 全文无 `stable`、`已审` 字样

## 10. 明确不覆盖

- 投资建议、估值定价、交易结构设计；
- 委托方战略与采购决策；
- 技术尽调的实质结论（需样品测试与产线验证）；
- 合作谈判条款与合同文本；
- 对被评估公司的管理评价。
