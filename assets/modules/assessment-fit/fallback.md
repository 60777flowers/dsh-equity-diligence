# assessment-fit · 降级调查清单（未 stable 方向）

> 适用：上游底稿缺失关键项、无客户验证信息、或预算不足时的最低交付标准。
> 降级只降低精度，不降低边界：**任何情况下都不给投资建议、不编造委托方背景**。

## 触发条件

- 缺 `ip.portfolio`/`financials.public`/`tech.origin` 等软引用；
- 无公开的客户验证或供货记录；
- 本单元可用工具调用 < 5 次。

## 最低必查（缺一即不得进入 `verified`）

1. a 项判断：产品是否落在委托方所需环节（用 `business.segment` + 产品页）；
2. b 项判断：是否有任何验证/供货公开记录（有就写阶段，没有写 `not_disclosed_after_search`）；
3. 一种可执行的合作方式 + 下一步；
4. `equityView` 至少给 `pending_dd` + 缺什么（不得留空）；
5. `conclusion.limitations` 至少 2 条。

## 降级后的写法

- 技术关联只有产品名称相似：`technologyFit` = `estimated` + `derivation`（对照方法与假设）；
- 验证阶段无公开信息：`commercialFit` = `pending_dd` + 需要客户验证报告；
- 股权信息不足：`equityView` = `pending_dd`，value 用 `需观察`，不得用"前景良好"；
- 无法判断合作方式：`approach` 给 1 个"送样验证"或"技术交流"并写清前提；
- 上游矛盾未解决：`conflict` + 两方依据，不得强行择一。

## 必须写入 `openQuestions`

- 客户验证报告与量产导入时间表；
- 产能、良率、报价与交付周期；
- 估值、轮次、老股与回购条款；
- 是否存在与委托方体系已有投资/合作关系（需 `investment.map` 确认）。

## 不得做

- 不得写"建议投资/谨慎投资/适合投资"等投资建议式结论；
- 不得因为技术匹配就写"投资价值高"；
- 不得联网搜索或自行描述委托方战略与合作意向；
- 不得用同行估值或行业均值替代公司特定事实；
- 不得在降级产物上写"已核验"或"可交付 IC"。
