# 资质、认定与准入（qualifications）

> 模块 id：`builtin/qualifications` ｜ 状态：**draft**（未经金融专家评审，不得称为 stable）
> 输出底稿：`qualifications`（typeVersion 1，cardinality one，scope company）
> 硬输入：`company.identity`；软引用：`business.segment`

## 1. 一句话目标

把公司拿到的**认定类资质（高企、专精特新、单项冠军）、行政许可（生产/经营/注册证）、体系与产品认证（IATF、ISO、CCC、CE 等）**列清，逐条核**有效期、发证主体、持证主体是否一致、许可范围**，并区分"已取得/公示中/已过期/已撤销"。

## 2. 输入、前置与输出

| 项 | 内容 | 缺失时 |
|---|---|---|
| `company.identity` | 全称、曾用名、统一社会信用代码、注册地 | `onMissing: block`，否则无法核对持证主体 |
| `business.segment`（软） | 产品线与应用领域 | 缺失只警告；无法判断"业务所需资质是否齐备" |

输出 `data`：`items[]`（主清单）、`certifications[]`（体系/产品认证）、`licenses[]`（行政许可）。`{{params.includeExpired}}` 为 false 时只列 `有效` 与 `公示中` 的资质，过期项移入 `openQuestions` 并在 `limitations` 说明；为 true 时全部列出并把 `status` 标 `已过期`。

## 3. 口径定义

### 3.1 四类资质，不要混在一张表里

| 类型 | 例子 | 发证/公示主体 | 归入字段 |
|---|---|---|---|
| **认定类** | 高新技术企业、专精特新中小企业、专精特新"小巨人"、制造业单项冠军、创新型中小企业 | 省科技/财政/税务联合、工信部/省工信厅 | `items[]` |
| **行政许可类** | 药品/医疗器械注册证、生产许可证、危化品经营许可证、排污许可证、安全生产许可证 | NMPA、省药监、应急、生态环境 | `licenses[]` |
| **体系认证类** | IATF 16949、ISO 9001/14001/45001、AEO 认证 | 认证机构、海关 | `certifications[]` |
| **产品准入类** | CCC、CE、UL、FCC、RoHS/REACH 符合性 | CQC 等认证机构、公告机构 | `certifications[]` |

- 认定类与行政许可类的区别：认定类给**政策优惠/荣誉**，行政许可类给**经营资格**；二者失效后果不同。
- **工信部优质中小企业梯度培育**是一条有序路径：创新型中小企业 → 专精特新中小企业 → 专精特新"小巨人"；三级各有公示批次与有效期，判断"处于哪一级"要看最新公示，不能凭公司自述越级表述。
- 协会证书、行业评选、客户供应商认证**不属于**行政许可，不得与许可证混列；客户认证归 `customers-orders`。

### 3.2 有效期与状态

状态取值：`有效` / `公示中` / `已过期` / `已撤销` / `已注销` / `暂停` / `未披露`。

- 常见有效期（以证书/公示文件载明为准，本文件只作检索提示）：高新技术企业资格 3 年；专精特新中小企业/"小巨人" 3 年；IATF 16949 证书 3 年（需年度监督审核）；医疗器械注册证 5 年。
- `validFrom`/`validTo` 必须取自证书或公示原文；只有"公示日期"时，`validTo` 写 `pending_dd` 并说明。
- 到期未续：`status=已过期`，不得继续按"具备资质"表述。
- 公示期内的资质：`status=公示中`，不得写成"已取得"。

### 3.3 主体一致性（最容易出错）

- 证书上的**持证主体名称**必须与 `company.identity` 的全称或曾用名一致；不一致时写清是哪个子公司持有。
- 集团证书、母公司证书不能自动覆盖子公司；子公司证书也不能算母公司。
- 生产地址、认证范围（产品/型号/工艺）必须与公司实际经营一致；地址变更未更新证书是常见瑕疵。
- 许可证的"许可范围"要抄原文要点（产品类别、型号、产能、经营方式），不得只写"具备资质"。

### 3.4 与业务需求的匹配

- 对照 `business.segment` 的产品线，判断"业务必需资质"是否齐备：如医疗器械需注册证/备案、汽车零部件需 IATF 16949、涉危化需安全生产/经营许可、出口欧盟需 CE。
- 缺失必需资质只写核查项（`openQuestions` / `flags`），**不推断"无证经营"**。

|---|---|---|---|---|

## 5. 字段与口径映射

| 字段 | 定义 | 缺失处理 |
|---|---|---|
| `items[].name` | 资质名称（官方全称） | 必填 |
| `items[].issuer` | 发证/认定主体 | 未披露写 `not_disclosed_after_search` |
| `items[].number` | 证书/公示编号 | 未披露写 `pending_dd` |
| `items[].validFrom` / `validTo` | 有效期起止 | 未披露写 `not_disclosed_after_search` |
| `items[].status` | 上文状态枚举 | 必填 |
| `items[].note` | 持证主体、许可范围、核验路径 | 必填 |
| `certifications[].name` / `number` / `validTo` / `status` | 认证名称、证书号、有效期、状态 | 未披露写 `pending_dd` 或 `not_disclosed_after_search` |
| `certifications[].scope` | 认证范围（产品/地址/标准） | 未披露写 `pending_dd` |
| `licenses[].name` / `number` / `validTo` / `status` | 许可名称、证号、有效期、状态 | 同上 |
| `licenses[].scope` | 许可范围（类别/型号/产能） | 未披露写 `pending_dd` |

## 6. 六态与边界

六态：`found` / `not_disclosed_after_search` / `lower_bound` / `pending_dd` / `conflict` / `not_applicable` / `not_reviewed` / `estimated`。

- `items[].number`、`items[].validTo`、`items[].status`、`certifications[].scope`、`licenses[].scope` 必须能落六态并带 note。
- `maxEstimatedRatio` 0：资质是登记/许可事实，**不允许估算**；查不到就写 `not_disclosed_after_search` 或 `pending_dd`。
- 只能 `pending_dd` 的：证书扫描件、许可范围原文、子公司持证情况、认证机构的审核报告。
- **公司特定事实（是否高企、证书编号、有效期）禁止用同行均值或行业惯例替代**。
- 不推断：不把"公示中"当"已取得"、不把"受理通知书"当"注册证"、不把协会证书当行政许可、不把集团证书覆盖子公司。

## 7. 常见误判（逐条对照）

1. **主体不一致**：子公司证书挂到母公司名下，或曾用名证书未做名称变更说明。
2. **过期未标**：证书已到期仍写"高新技术企业"，`status` 未更新。
3. **受理当取得**：把注册申请受理通知书、备案凭证当成注册证。
4. **协会证书当许可**：把行业协会评选、客户供应商认证写成经营资质。
5. **范围扩大解释**：认证范围只覆盖某型号/某地址，却表述为"全公司通过认证"。
6. **高企到期未重新认定**：资格 3 年期满未重新认定，仍按 15% 优惠税率口径引用。
7. **公示期当发证**：公示名单上有名字就写"已获得"。
8. **证书截图当官方核验**：只凭公司官网证书图片，未在官方库核验编号。

## 8. 验收要点

- `minEvidence: 2`、`minCoverage: 0.7`；`data.items` ≥1 行（确无任何资质时插 1 行 `not_applicable` 占位并说明检索范围）。
- 每条 `items`：名称、发证主体、编号、有效期、状态五要素齐全或有六态说明。
- 持证主体与 `company.identity` 一致，或明确标注"由子公司 E01 持有"。
- 有效期已与 asOf 比较：过期项必须 `status=已过期`（`includeExpired=false` 时移入 `openQuestions`）。
- 业务必需资质（对照 `business.segment`）缺失时写入 `openQuestions` 并说明依据。
- 证书编号在官方库可查；仅有截图时 `verificationStatus=partial`。

## 9. 与其他模块的关系

- **上游**：`company.identity`（持证主体核对）。
- **下游**：`assessment-fit`（准入壁垒）、`red-flags`（资质缺失/过期线索）、`deliverable`（资质表）。
- **交叉**：`business.segment`（业务所需资质）、`esg.ehs`（排污许可、安全生产许可，避免重复登记：本模块只记"有/无与有效期"，环保技术细节归 `esg.ehs`）、`regulatory-compliance`（处罚导致资质撤销）。
- 与 `ip-portfolio` 的边界：知识产权归 `ip-portfolio`，本模块只管资质/许可/认证。

## 10. 版本与状态

- 模块状态：`draft`，未经金融专家评审。
- 资质有效期与状态变化频繁：重跑必须以 `asOf` 重新比对有效期，不得沿用上一版状态。
