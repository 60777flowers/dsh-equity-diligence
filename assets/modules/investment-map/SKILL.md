# 对外投资版图（investment-map）

> 模块状态：`draft`。方法论可执行、有门与 rubric，**尚未经过金融专家评审**。
> 不得在交付物中标注 `stable` 或“专家已审”。

> **来源：人工实现版本。** 本模块由部门内部实战 skill（`investigate-equity-structure` v7）逐条转写而来，
> 九类出口硬枚举、收集-审核双链路、7+N 分表口径、方向口径纪律均来自真实项目沉淀。
> 其余 24 个模块是子代理按公开信息最佳实践编写的初稿，**与本模块不在同一成熟度上**。

## 1. 一句话目标

回答“**A公司系把钱/控制投到了哪里**”：把目标体系作为出资方/控制方的投资平台按九类出口归位，
逐平台列出被投实体与持股路径，形成可分平台交付的 `investment.map`。

## 2. 方向口径（全文统一，最先读）

### 2.1 只查“投出去”

- **被调查对象（A公司体系）** = 目标公司本体 + 其主导群体（实控/经营主导/创始群体及家庭成员）。
- **投资平台** = A公司系作为**出资方或控制方**设立的载体：直投主体、GP/管理公司及其基金、
  LP 参与的基金、境外持股层与经营主体、合资公司、国内基地、家族/个人平台。
- 判断标准：**A公司系出钱或控制**（任 GP、任 LP、控股股东、实际控制）。
- **被投实体** = 平台**对外投出/控股**的实体；判断标准是“钱最终落到该实体”（平台持有其股权/份额）。

### 2.2 明确不查（反向口径）

- 不查“谁投资了 A公司”：A公司自身股东结构、被并购、被入股、二级市场增持。
- 不查基金里除 A公司系以外的其他 LP 是谁、他们各自投了什么。
- 外部出资人只在影响“平台对外投了什么”的判断时，在 `note` 简记一句。

### 2.3 方向自检（每条记录都过一遍）

| 问题 | 归属 |
|---|---|
| 这个主体是 A公司系出钱/控制的吗？ | 是 → 平台；否 → 不收录 |
| 这条投资是平台投出去的吗？ | 是 → 实体；否（别人投进来）→ 不收录 |
| 这个 LP 是 A公司系吗？ | 是 → 记录份额；否 → 不展开 |
| 这是 A公司的股东吗？ | 是 → 反向信息，不收录 |

## 3. 九类出口

| 编号 | 分类 | 定义/判断标准 | 记录要点 |
|---|---|---|---|
| 1 | 直接投资 | A公司或控股子公司直接持股的实体（含并购控股、二级市场投资） | 投资主体是本部还是哪个子公司；直接/间接；比例；时间 |
| 2 | 合作基金-GP | A公司控股 GP/管理公司的基金，出资与管理双主导 | GP 实体股权结构、基金全称、管理人、备案、投向 |
| 3 | 合作基金-主导LP | A公司为最大/控股 LP，GP 由外部机构担任 | LP 份额（金额+比例）、GP、其他重要 LP、被投简列 |
| 4 | 合作基金-财务LP | 小比例财务出资，不主导 | 基金全称、管理人、出资额/比例、被投简列 |
| 5 | 海外平台 | 境外经营主体、境外持股层、境外资本平台 | 境内层→境外层→经营主体→基地的完整链条，逐层比例 |
| 6 | 合资公司 | 与外部产业方共同设立/收购的合资或联营实体 | 合资方及比例、注册资本、控制权归属 |
| 7 | 国内基地 | 国内生产基地、产业园、区域运营主体 | 基地名称、注册地、持股结构、职能 |
| 8 | 主导群体家族（第一） | 影响最大的实控/经营主导/创始群体 | 家族核心平台→下层基金→被投实体 |
| 9 | 主导群体家族（第二/第三） | 同上，至多 3 个群体 | 超过 3 个取影响前 3，其余进说明页待关注 |

### 3.1 分类判断规则

- “XX 资本/基金”类主体：先判 GP 归属，再判 LP 份额；产业方控股 GP → 第 2 类；只是大 LP → 第 3/4 类。
- 间接持股（经基金/持股平台）不算直接投资，在第 1 类行注明“经 XX 间接”。
- 境外主体按“注册地 + 职能”归第 5 类；境内生产基地归第 7 类；重叠时按主要职能归一类并在 `note` 说明。
- 主导群体判定依据公告口径与公开事实；法定实控、经营主导、创始三者可分离，分离时各成体系。
- 用户给出的分类先核实：名称可能记错（音近/形近、曾用名、品牌名与工商名不一致），股权关系可能记反。

## 4. 输入与前置

| 输入/参数 | 必要性 | 缺失时的处理 |
|---|---|---|
| `company.identity` | 必须（`onMissing: block`） | 不启动；先确认主体 |
| `ownership.chain` | 必须（`onMissing: block`） | 不启动；平台归属依赖控制链 |
| `{{params.maxPlatforms}}` | 默认 40，范围 5–120 | 超出上限时保留影响最大的平台，其余进 `openQuestions` |
| `{{params.includeOverseas}}` | 默认 true | false 时第 5 类写 `not_reviewed` 并说明 |
| `business.segment` | 软引用 | 缺失只警告；用于判断“与主业协同”的平台归类 |

## 5. 平台编号与分区

### 5.1 编号规则（稳定键）

- 平台编号 `P01`、`P02`…… 按 1→9 顺序分配，类内按登记顺序。
- **编号一旦分配不再改变**：平台更名不改号，旧名写入该平台 `name` 或 `note`。
- 平台合并/拆分时：保留原编号给承接主体，新增编号给新主体，旧编号标 `merged_into`。
- 已退出/注销的平台保留编号与记录，`entities[].status` 标“已退出”，不得删除。
- 编号连续、不跳号；跳号只允许在 `openQuestions` 说明原因。

### 5.2 分区（partitionKey）

| 分区 | `data` 形状 | 内容 |
|---|---|---|
| `_summary` | `mode=summary` | `platformCount`、`entityCount`、`overseasCount`、`categories[]`、`platforms[]` |
| `P01`…`Pnn` | `mode=platform` | `platformId`、`name`、`fullName`、`category`、`role`、`vehicles[]`、`entities[]`、`evidenceSummary` |

规则：

- 每个工单只处理一个分区：summary 分区只做汇总与一致性，不改平台明细；平台分区只写本平台。
- summary 的 `platformCount` 必须等于平台分区数量；`entityCount` 等于各平台实体数之和（多路径去重后）。
- 平台分区不得写入其他平台的数据；跨平台实体在各自平台分区各写一次。

## 6. 检索计划

### 6.1 通用六步（每类都走一遍）

1. 公告检索：`对外投资`、`参与投资`、`设立基金`、`增资`、`股权转让`、`权益变动`、`年度报告`、`招股书`。
2. 摘出主体名、出资额、份额、GP/LP 角色、时间；方向过滤（只留 A公司系出钱/控制）。
3. 工商交叉：成立日、注册资本、股东/合伙人、对外投资。
4. 中基协备案：基金名称、管理人、备案号、投向。
5. 境外：港交所披露易/招股书/当地登记 + 英文检索。
6. 媒体盘点只作线索，必须回公告/工商核名；对不上标“存疑”，不硬填。

### 6.2 九类检索词

| 分类 | 中文检索词 | 英文/当地语言 |
|---|---|---|
| 1 直接投资 | `[A公司] 对外投资`、`[A公司] 参股`、`[子公司名] 股权转让`、年报“主要参股公司” | `[英文名] equity investment`、`[英文名] subsidiary` |
| 2 基金-GP | `[A公司] 设立基金`、`[A公司] 合伙企业 GP`、`[A公司] 企业管理中心` | `[英文名] GP fund`、`[英文名] fund manager` |
| 3 基金-主导LP | `[A公司] 参与投资 [基金名]`、`[A公司] 认购 出资份额`、`[基金名] 合伙人` | `[英文名] limited partner` |
| 4 基金-财务LP | `[A公司] 入伙`、`[A公司] 认购 [基金名] 份额`、媒体“A公司作LP” | `[英文名] LP interest` |
| 5 海外平台 | `[A公司] 境外子公司`、`[A公司] 新加坡/泰国/美国`、招股书“公司架构” | `[英文名] overseas subsidiary`、`[主体名] UEN/ACRA/SEC` |
| 6 合资公司 | `[A公司] 合资`、`[A公司] 共同出资设立`、`[A公司] 联营企业` | `[英文名] joint venture` |
| 7 国内基地 | `[A公司] 生产基地`、`[A公司] 新设公司`、官网“工厂分布” | `[英文名] manufacturing base` |
| 8/9 家族平台 | `[代表人物] 家族`、`[代表人物] 持股平台`、`[代表人物] 一致行动人`、工商“关联企业” | `[person name] family office` |

### 6.3 平台完整性审核（四维度）

- **基准覆盖**：以最新年报“主要控股/参股公司”、招股书“公司架构”、公告汇总为基准，逐项核对是否已收录。
- **人物家族盲区**：主导群体及其配偶、子女、父母、兄弟姐妹的公开平台是否扫过。
- **境外盲区**：港/新/美/开曼/BVI 是否至少各一轮英文检索。
- **分类归位**：每个平台是否只归一类，跨类是否在 `note` 说明。

## 7. 字段与口径

### 7.1 平台字段

| 字段 | 口径 |
|---|---|
| `platformId` | `P01` 形式，稳定不变 |
| `name` | 展示名（简称），去除空白与非法字符 |
| `fullName` | 工商/登记全称 |
| `category` | 1–9 之一，**写成字符串 `"1"`–`"9"`**（与 7+N 分表编号一致，交付构建器按 `Number(category)` 映射分表） |
| `role` | `直投主体`/`GP`/`管理人`/`主导LP`/`财务LP`/`境外持股层`/`境外经营主体`/`合资方`/`基地`/`家族平台` |
| `vehicles[]` | 上层载体：基金、合伙企业、持股公司；写 `name`/`fullName`/`id`/`role`/`relation`/`note` |
| `entities[]` | 被投实体：`name`/`fullName`/`path`/`directPct`/`indirectPct`/`totalPct`/`status`/`note` |
| `evidenceSummary` | 本平台证据条数与类型摘要（如“公告 2 条、工商 1 条、基金备案 1 条”） |

### 7.2 实体与路径字段

- `path` 写成箭头链：`A公司 → P01 → E01`，中间层全部列出；多层用 `→` 分隔。
- `directPct`/`indirectPct`/`totalPct` 口径同 `ownership-chain`；间接比例按路径相乘。
- `status`：`在持`/`已退出`/`已注销`/`待核`/`部分退出`；已退出必须写退出时间与对价（可得时）。
- 同一实体多路径：**每个平台分区各写一行**，不跨平台去重；`path` 不同、比例按各自路径。
- 实体全称以工商登记为准；品牌名进 `name`，全称进 `fullName`。

### 7.3 证据要求（每平台 ≥3）

- 每个平台至少 3 条证据，且覆盖三类事实中的至少两类：
  1. 平台存在与身份（全称、成立、登记/备案）；
  2. A公司系的出资或控制关系（股权、LP 份额、GP 归属）；
  3. 平台对外投出的实体（至少一家实体可回查）。
- 证据不足 3 条的平台：`evidenceSummary` 写明缺口，平台分区仍产出，但 `flags` 标 `attention`。
- 同一新闻稿转载只算一条 `originGroupId`。

## 8. 去重与多路径

- 平台去重：同一统一社会信用代码/注册号只保留一个编号；更名不新建。
- 实体去重：按工商全称去重；同一实体多平台持股时保留多行，不合并比例。
- 路径去重：同一平台内同一实体的同一路径只写一次；不同路径分行。
- `_summary.entityCount` 按**实体全称去重**计数，不按行数计数。
- 跨平台路径表是交付与工作簿的映射依据，本模块必须提供可直接展开的 `path`。

## 9. 六态与边界

- `found`：公告/工商/备案明确，且至少两类来源一致。
- `not_disclosed_after_search`：写清查过的库、词、日期；能对上 `search.ledger`。
- `lower_bound`：只用于“至少 N 家被投”类事实。
- `pending_dd`：需基金合伙协议、LP 名册、境外注册证书才能确认。
- `conflict`：公告与工商比例/名称不一致，保留候选与裁决。
- `not_applicable`：平台无对外投资（如纯持股层），写 `not_applicable` 并说明。
- `not_reviewed`：预算耗尽或未分配；不得伪装成“无投资”。
- `estimated` 本模块禁用；不得用同行投资版图替代本公司版图。

## 10. 常见误判

1. **方向搞反**：把 A公司的股东、把“谁投了 A公司”写成平台。
2. **LP 名单当被投**：基金的其他 LP 不是被投实体。
3. **GP 与基金混为一行**：GP 是管理主体，基金是出资载体，分行记录。
4. **更名重复编号**：同一主体更名后新建 P 号，导致重复计数。
5. **已退出当现持**：退出标的必须标状态与时间。
6. **战略合作当投资**：框架协议、意向书、战略合作不等于出资。
7. **间接当直接**：经基金/持股平台的持股不是直投。
8. **境外曾用名重复**：同一境外主体两个名字被算成两个平台。
9. **小额二级市场持仓当核心平台**：按影响与金额排序，不把全部持仓都列为核心。
10. **基金“暂定名”当工商名**：以工商注册名为准，公告拟定名进 `note`。

## 11. 验收要点

- 九类各至少一轮检索记录，空类在 `openQuestions` 说明“确实无”或“未查到”。
- 每个平台分区 ≥3 条证据，`evidenceSummary` 与证据数一致。
- 平台编号连续稳定；summary 计数与平台分区数、实体去重数一致。
- 每个实体有可展开的 `path`；多路径在各平台分区均有行。
- 方向违规为 0：不出现“A公司股东/被投/被增持”类记录。
- 每条 material claim 至少一条 `role=supports`；不出现 `estimated`。

## 12. 与其他模块的关系

- 上游：`company.identity`、`ownership.chain`（平台归属与控制关系）。
- 下游：`deliverable`（7+N 专项、综合工作簿）、`red-flags`（关联交易/资金占用触发器的输入）。
- 软引用：`business.segment`（协同方向）、`org.people`（人物平台）。
- 被投实体的经营与财务由各自模块调查，本模块只给名单、路径与比例。

## 13. 已知缺口（draft 阶段）

- 基金 LP 份额与备案信息更新滞后，需以最新备案与公告为准。
- 境外层（BVI/开曼）常只能拿到注册代理摘要，穿透深度受限。
- 家族平台依赖公开线索，未证实的只能标“疑似，未证实”。
- 平台完整性依赖基准清单的时效；年报更新后需重跑本模块。
